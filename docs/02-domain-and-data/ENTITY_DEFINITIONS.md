# 实体定义

> 用途说明：逐项定义核心实体的身份、职责、属性、约束、允许操作和删除影响，为领域实现、接口和数据库结构提供共同依据。
>
> 状态：初稿 / 待评审
>
> 最后更新日期：2026-07-30

## 1. 实体定义规则

- 实体通过稳定标识区分，不通过显示名称区分。
- 实体字段描述逻辑含义，不等同于数据库列或代码属性。
- “必填”表示成功持久化时必须存在，不代表界面一定要求用户逐项输入。
- 所有用户业务数据都位于保险库保护范围内。
- `is_sensitive` 控制运行时展示和复制保护，不表示非敏感字段可以明文保存。
- 删除规则在数据生命周期确定前保持显式，不允许静默级联。

## 2. 通用属性

| 属性 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | `EntityId` | 是 | 创建后稳定且不可变 |
| `createdAt` | `Timestamp` | 是 | 实体首次成功创建时间 |
| `updatedAt` | `Timestamp` | 是 | 最近一次成功修改时间 |
| `deletedAt` | `Timestamp?` | 待定 | 只有选择软删除方案后使用 |
| `revision` | `Integer?` | 待定 | 需要乐观并发控制时使用 |

通用约束：

- 时间由应用服务统一提供，不依赖用户输入。
- 修改显示名称不得创建新的实体标识。
- 实体标识不得包含用户名、网址或其他敏感内容。
- 从不支持的新数据版本读取实体时，应停止写入并进入兼容处理，而不是丢弃未知数据。

## 3. Vault（保险库）

### 3.1 定义

受统一安全策略保护的数据容器和隔离边界。MVP 中，一个应用数据目录只管理一个保险库。

### 3.2 属性

| 属性 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | `EntityId` | 是 | 自动生成 | 保险库内部标识 |
| `displayName` | `DisplayName` | 是 | “我的保险库” | 用户可见名称 |
| `dataVersion` | `DataVersion` | 是 | 当前版本 | 逻辑数据格式版本 |
| `createdAt` | `Timestamp` | 是 | 当前时间 | 创建时间 |
| `updatedAt` | `Timestamp` | 是 | 当前时间 | 更新时间 |

不允许作为普通属性：

- 主密码。
- 明文加密密钥。
- 可直接解锁的派生结果。
- 真实恢复密钥。

### 3.3 不变量

- `id` 创建后不变。
- `dataVersion` 必须是应用明确支持或可迁移的版本。
- 保险库不能直接引用其他保险库中的对象。
- 锁定状态是应用会话状态，不建议只作为可篡改的普通布尔字段持久化。

### 3.4 操作

- 创建保险库。
- 请求解锁。
- 锁定。
- 验证数据版本。
- 修改显示名称。

### 3.5 删除影响

删除保险库将影响其全部分类、网站、账号和字段，属于最高风险操作。MVP 不提供普通界面内的“删除保险库”功能；如未来提供，必须使用独立流程和备份提示。

## 4. Category（分类）

### 4.1 定义

网站的主要组织层级，例如“工作”“开发”“社交”。

### 4.2 属性

| 属性 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | `EntityId` | 是 | 自动生成 | 分类标识 |
| `vaultId` | `EntityId` | 是 | 当前保险库 | 所属保险库 |
| `name` | `DisplayName` | 是 | 无 | 分类名称 |
| `sortOrder` | `SortOrder` | 是 | 同级末尾 | 显示顺序 |
| `createdAt` | `Timestamp` | 是 | 当前时间 | 创建时间 |
| `updatedAt` | `Timestamp` | 是 | 当前时间 | 更新时间 |

### 4.3 不变量

- `vaultId` 对应存在的当前保险库。
- `name` 去除无意义首尾空白后不能为空。
- `sortOrder` 只在同一保险库的分类中比较。
- 重命名不改变网站归属。

### 4.4 操作

- 创建。
- 重命名。
- 调整顺序。
- 查询网站数量。
- 请求删除。

### 4.5 删除影响

- 空分类可以在确认后删除。
- 非空分类必须先选择移动网站、取消或按明确规则连同内容处理。
- 默认不允许无提示删除其网站。

### 4.6 待决策

- 同一保险库不允许规范化后同名分类。
- 删除非空分类时是否提供系统“未分类”目标。
- 是否对系统默认分类设置不可删除限制。

## 5. Website（网站）

### 5.1 定义

代表一个网站或服务，保存其账号之间共享的信息。

### 5.2 属性

| 属性 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | `EntityId` | 是 | 自动生成 | 网站标识 |
| `vaultId` | `EntityId` | 建议 | 当前保险库 | 范围约束，物理保留待定 |
| `categoryId` | `EntityId` | 是 | 用户选择 | 所属分类 |
| `name` | `DisplayName` | 是 | 无 | 网站或服务名称 |
| `primaryUrl` | `Url?` | 否 | 空 | 主网址 |
| `iconRef` | `IconReference?` | 否 | 默认图标 | 本地图标引用 |
| `sortOrder` | `SortOrder` | 是 | 同级末尾 | 分类内顺序 |
| `createdAt` | `Timestamp` | 是 | 当前时间 | 创建时间 |
| `updatedAt` | `Timestamp` | 是 | 当前时间 | 更新时间 |

### 5.3 不变量

- `categoryId` 对应存在且属于同一保险库的分类。
- `name` 去除无意义首尾空白后不能为空。
- `primaryUrl` 非空时必须符合网址值对象规则。
- 网站移动分类时，账号和字段关系保持不变。
- 网站不直接保存具体账号的密码。

### 5.4 操作

- 创建。
- 修改名称、网址和图标引用。
- 移动到其他分类。
- 查询账号。
- 请求打开或复制网址。
- 请求删除。

### 5.5 删除影响

删除网站会影响其所有账号和字段。执行前必须：

- 计算账号数量。
- 向用户展示影响。
- 获得明确确认。
- 按数据生命周期策略处理子对象。

### 5.6 待决策

- 同一分类允许同名网站，但界面必须提示并展示网址等区分信息。
- `primaryUrl` 是否自动补全协议，或只提示用户修正。
- 是否需要网站级备注。

## 6. Account（账号）

### 6.1 定义

网站下的一个具体身份。账号使用显示名称区分用途，实际用户名、密码和其他信息由账号字段保存。

### 6.2 属性

| 属性 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | `EntityId` | 是 | 自动生成 | 账号标识 |
| `vaultId` | `EntityId` | 建议 | 当前保险库 | 范围约束，物理保留待定 |
| `websiteId` | `EntityId` | 是 | 当前网站 | 所属网站 |
| `displayName` | `DisplayName` | 是 | 待定 | 例如“私人账号” |
| `sortOrder` | `SortOrder` | 是 | 同级末尾 | 网站内顺序 |
| `createdAt` | `Timestamp` | 是 | 当前时间 | 创建时间 |
| `updatedAt` | `Timestamp` | 是 | 当前时间 | 更新时间 |

### 6.3 不变量

- `websiteId` 对应存在的网站。
- 账号和网站位于同一保险库。
- `displayName` 去除无意义首尾空白后不能为空。
- 同一网站允许多个账号。
- 账号可以暂时没有任何字段，但界面应提供添加入口。
- 修改账号不影响同网站其他账号。

### 6.4 操作

- 创建。
- 修改显示名称。
- 调整顺序。
- 添加、更新、排序和移除字段。
- 请求复制字段。
- 请求删除。

### 6.5 保存边界

账号及其字段建议在一次事务中保存：

- 新账号和初始字段一起创建。
- 编辑时同时校验所有字段。
- 任一字段写入失败时，避免只保存部分更改。
- 更新成功后再产生“保存成功”反馈。

### 6.6 删除影响

删除账号只影响该账号及其字段，不得影响网站或同网站其他账号。

### 6.7 待决策

- 同一网站不允许规范化后同名账号显示名称。
- 新账号的默认显示名称。
- 账号是否可以在网站之间移动。
- 收藏作用于账号还是网站。

## 7. AccountField（账号字段）

### 7.1 定义

属于账号的一项具名信息。基础字段和自定义字段使用同一实体结构，通过 `systemRole` 区分系统语义。

### 7.2 属性

| 属性 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | `EntityId` | 是 | 自动生成 | 字段标识 |
| `accountId` | `EntityId` | 是 | 当前账号 | 所属账号 |
| `systemRole` | `FieldRole?` | 否 | 空 | 基础字段角色 |
| `label` | `FieldLabel` | 是 | 无 | 用户可见名称 |
| `fieldType` | `FieldType` | 是 | `text` | 字段语义类型 |
| `value` | `FieldValue` | 否 | 空 | 受保护字段值 |
| `isSensitive` | `Boolean` | 是 | 按角色或类型 | 默认展示保护 |
| `sortOrder` | `SortOrder` | 是 | 末尾 | 账号内顺序 |
| `createdAt` | `Timestamp` | 是 | 当前时间 | 创建时间 |
| `updatedAt` | `Timestamp` | 是 | 当前时间 | 更新时间 |

### 7.3 系统角色

| 角色 | 是否唯一 | 默认类型 | 最低敏感规则 |
| --- | --- | --- | --- |
| `username` | 是 | `text` | 可由用户设为敏感 |
| `password` | 是 | `password` | 必须敏感 |
| `email` | 是 | `email` | 可由用户设为敏感 |
| `note` | 是 | `multiline` | 可由用户设为敏感 |
| 空 | 否 | 用户选择 | 由用户选择或类型默认值决定 |

“唯一”指同一账号内相同非空系统角色至多一个。

### 7.4 不变量

- `accountId` 对应存在的账号。
- `label` 去除无意义首尾空白后不能为空。
- `password` 角色不能保存为非敏感。
- 自定义字段的 `systemRole` 为空。
- 未知 `fieldType` 必须被保留。
- 字段显示状态不作为持久化秘密属性；重新进入或锁定后敏感字段恢复隐藏。

### 7.5 操作

- 修改标签。
- 修改值。
- 修改类型。
- 修改敏感属性。
- 调整排序。
- 请求显示或隐藏。
- 请求复制。
- 删除。

### 7.6 删除影响

删除字段只影响该字段。删除系统角色字段时，界面应说明其作用，但不应自动删除账号。

### 7.7 待决策

- 同一账号不允许规范化后相同字段标签。
- 空值字段是否保留。
- 修改字段类型时如何转换不兼容值。
- 用户是否可以删除所有基础字段。

## 8. Tag（标签，V1 候选）

### 8.1 定义

跨分类标记对象的轻量方式，不改变对象主要归属。

### 8.2 候选属性

| 属性 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `EntityId` | 标签标识 |
| `vaultId` | `EntityId` | 所属保险库 |
| `name` | `DisplayName` | 标签名称 |
| `color` | `ColorToken?` | 可选视觉标识 |
| `createdAt` | `Timestamp` | 创建时间 |
| `updatedAt` | `Timestamp` | 更新时间 |

### 8.3 约束

- 删除标签不删除被标记对象。
- 标签不能跨保险库使用。
- 目标对象范围仍待决策，因此不进入 MVP 物理模型。

## 9. TagAssignment（标签分配，V1 候选）

表示标签和网站或账号之间的多对多关系。

候选约束：

- 同一标签不能重复分配给同一对象。
- 标签和目标必须属于同一保险库。
- 物理结构应尽可能保持外键完整性。
- 网站标签与账号标签是否分表，由数据库设计决定。

## 10. 非实体概念

以下内容不应被误建模为普通持久化实体：

| 概念 | 建议表示 |
| --- | --- |
| 当前解锁状态 | 受控应用会话 |
| 当前显示的明文密码 | 临时界面状态 |
| 搜索输入 | 临时应用状态 |
| 复制成功提示 | 临时界面反馈 |
| 主密码 | 用户输入的短生命周期敏感值 |
| 明文加密密钥 | 安全组件管理的短生命周期密钥材料 |
| 默认浏览器 | 平台服务 |

## 11. 实体关系验证

每次写入至少检查：

- [ ] 父对象存在。
- [ ] 父子对象位于同一保险库。
- [ ] 稳定标识没有被修改。
- [ ] 必填名称和标签有效。
- [ ] 系统角色没有冲突。
- [ ] 密码角色保持敏感。
- [ ] 排序范围正确。
- [ ] 删除影响已经明确。

- [x] 确定同名规则。
