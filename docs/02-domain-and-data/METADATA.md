# 元数据

> 用途说明：定义系统维护的标识、时间、排序、版本、删除状态等元数据，以及其隐私、加密和展示规则。
>
> 状态：初稿 / 待评审
>
> 最后更新日期：2026-07-30

## 1. 定义

元数据是描述对象和系统状态的辅助信息，不是用户直接保存的秘密值。元数据仍可能暴露用户使用了哪些网站、何时修改账号及数据规模，因此原则上属于私密信息。

## 2. 设计原则

- 只收集完成核心功能所需的元数据。
- 默认与保险库业务数据一起加密。
- 不把访问历史、行为分析和遥测伪装成必要元数据。
- 元数据由应用维护，用户不直接编辑内部标识和版本。
- 数据库约束和迁移不能依赖本地化显示文本。
- 时间和排序必须具有稳定、可比较的机器表示。

## 3. 核心元数据

| 名称 | 适用对象 | 必填 | 用途 |
| --- | --- | --- | --- |
| `id` | 所有实体 | 是 | 稳定标识 |
| `createdAt` | 所有实体 | 是 | 创建时间 |
| `updatedAt` | 所有实体 | 是 | 最近成功修改时间 |
| `sortOrder` | 分类、网站、账号、字段 | 是 | 同级显示顺序 |
| `dataVersion` | 保险库或数据集 | 是 | 迁移和兼容 |
| `deletedAt` | 可软删除实体 | 条件必填 | 回收站状态 |
| `deletionGroupId` | 删除批次对象 | 条件必填 | 级联恢复边界 |
| `revision` | 需要并发检查的实体 | 待定 | 防止覆盖更新 |

## 4. 标识

要求：

- 在其有效范围内唯一。
- 创建后不变。
- 不包含名称、网址、用户名或时间等可推测业务信息。
- 可以随备份、恢复和迁移保持。
- 不显示给普通用户。

MVP 使用随机 UUID v4，并在 SQLite 中保存为 16 字节。它不按时间排序，也不从标识暴露创建时间。

## 5. 时间

### 5.1 存储

- 使用 UTC 或等价的无歧义时间基准。
- 保存足够精度，但不因追求纳秒精度增加复杂度。
- 数据库存储格式由技术栈决定。
- 界面根据本地时区格式化。

### 5.2 更新时间规则

- 创建时同时写入 `createdAt` 和 `updatedAt`。
- 成功修改业务数据后更新 `updatedAt`。
- 仅查看、复制、搜索或打开网址不更新 `updatedAt`。
- 排序变化是否更新对象 `updatedAt` 由数据库设计统一确定，建议更新。
- 失败或回滚的事务不更新时间。

### 5.3 不默认记录

- `lastViewedAt`
- `lastCopiedAt`
- `lastOpenedAt`
- 使用次数
- 搜索历史

这些数据不是核心功能所需，可能泄露使用习惯，MVP 不收集。

## 6. 排序

- 分类在保险库内排序。
- 网站在分类内排序。
- 账号在网站内排序。
- 字段在账号内排序。
- 排序值只在相同父对象范围内有意义。
- 重排使用事务，不能留下重复或部分更新状态。
- MVP 可以使用连续整数；高级稀疏排序以后再评估。

## 7. 数据版本

区分：

| 版本 | 作用 |
| --- | --- |
| 应用版本 | 用户安装的软件发布版本 |
| 保险库格式版本 | 外层安全头、密钥包装和密文容器格式 |
| 数据模型版本 | 解密后逻辑实体结构 |
| 数据库结构版本 | 表、索引和约束迁移版本 |

这些版本可以在初期保持相同迁移节奏，但概念上不能混为一谈。

版本规则：

- 应用必须识别版本后再写入。
- 不支持的新版本默认只读或拒绝打开。
- 迁移成功后才更新版本。
- 版本字段不得由用户直接修改。

## 8. 删除元数据

软删除对象记录：

- `deletedAt`
- `deletionGroupId`
- 原父关系，若恢复需要且现有关系会改变

规则：

- 活跃对象的 `deletedAt` 为空。
- 删除批次标识在一次级联操作中相同。
- 恢复后清除删除状态，但保留原始 `createdAt`。
- 恢复属于修改，应更新 `updatedAt`。
- 永久删除后不保留可正常查询的墓碑记录，除非迁移或同步未来明确需要。

## 9. 敏感性

| 元数据 | 泄露风险 | 保护方式 |
| --- | --- | --- |
| 网站和账号数量 | 暴露数据规模 | 保险库内加密 |
| 分类名和字段标签 | 暴露用户用途 | 保险库内加密 |
| 时间戳 | 暴露活动时间 | 保险库内加密 |
| 对象关系 | 暴露账号结构 | 保险库内加密 |
| 排序 | 暴露用户偏好 | 保险库内加密 |
| 文件对版本和 schema | 通常非秘密 | 放入数据库元数据或备份完整性清单 |
| 随机盐 | 非秘密 | 可放安全头，不要求保密 |

最终外层安全头内容由加密设计确定。

## 10. 配置不属于领域元数据

以下属于应用配置：

- 主题。
- 剪贴板条件清除时长。
- 剪贴板清除时长。
- 窗口大小和位置。
- 语言。

配置不得包含：

- 主密码。
- 明文密钥。
- 明文字段值。
- 完整搜索历史。

安全设置可以放在独立配置文件，但必须防止被篡改为危险值时静默降低保护。

## 11. 日志和诊断

普通日志允许记录：

- 不含业务标识的错误类别。
- 应用版本。
- 数据格式版本。
- 操作是否成功。

默认禁止记录：

- 实体名称。
- 网址。
- 用户名。
- 字段标签和值。
- 主密码和密钥。
- 搜索词。
- 可用于关联用户数据的完整稳定标识。

如果诊断确需标识对象，应使用当前进程内不可逆、不可跨会话关联的临时标识。

## 12. 导出和备份

- 加密备份保留恢复所需元数据。
- 明文导出应最小化内部元数据，通常不导出内部标识、删除批次和数据库版本。
- 导入时生成或映射稳定标识，处理冲突。
- 时间戳是否保留由导入导出格式明确规定。

## 13. 验收标准

- [ ] 所有实体具有稳定标识和时间戳。
- [ ] 重命名对象不改变标识。
- [ ] 查看、复制和搜索不记录使用历史。
- [ ] 时间以无歧义格式保存并按本地时区显示。
- [ ] 排序只影响同级对象。
- [ ] 删除批次可以区分级联删除来源。
- [ ] 元数据默认随保险库加密。
- [ ] 日志不包含业务名称、网址或稳定标识。
- [ ] 数据版本只有迁移成功后更新。

## 14. 待决策事项

- [x] 标识使用随机 UUID v4；时间使用 UTC Unix 毫秒整数。
- [x] MVP 不增加 `revision` 字段，由应用层检测同进程编辑覆盖。
- [ ] 确定排序变化是否更新所有受影响对象时间。
- [ ] 确定安全配置的完整性保护方式。
- [ ] 确定明文导出的时间戳保留规则。
