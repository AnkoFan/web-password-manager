# 安全漏洞披露流程

> 状态：M3 流程已定义 / GitHub 私有漏洞报告待仓库公开前启用
>
> 最后更新日期：2026-07-31

## 1. 报告渠道

仓库公开前，不在公开 Issue、Discussion、PR 或社交平台提交尚未修复的漏洞细节。

公开时应启用 GitHub Private Vulnerability Reporting。启用后使用：

`https://github.com/AnkoFan/web-password-manager/security/advisories/new`

若该入口不可用，报告者只需公开提交“不含技术细节”的请求，要求维护者提供私密渠道；不得附加保险库、密码、Token、转储或可利用样本。

## 2. 报告内容

- 受影响的完整应用版本和提交 SHA；
- Windows 与 WebView2 版本；
- 漏洞类别、影响和前置条件；
- 使用纯虚构数据的最小复现步骤；
- 是否涉及安全头、数据库、备份、安装包或更新链；
- 建议缓解措施和披露时间协调方式。

不要提交真实保险库、数据库密钥、DPAPI 明文材料、个人数据或第三方系统凭据。需要夹具时使用明确的 `TEST-ONLY` 标记。

## 3. 维护者处理

1. 在 3 个工作日内确认收到，不等同于确认漏洞成立。
2. 建立私有安全通告并限制访问。
3. 复现、分级并确认受影响版本；所有测试只使用虚构数据。
4. 对严重/高危问题立即停止发布并准备缓解建议。
5. 在私有分支修复并运行完整安全、迁移和安装门禁。
6. 邀请报告者或独立评审者复测。
7. 协调发布、CVE（如适用）和公开披露时间。

## 4. 严重度参考

- 严重：无需已知主密码读取保险库、远程代码执行、发布签名私钥泄露、可静默替换已验证安装包。
- 高：绕过锁定读取秘密、可靠破坏最后有效副本、KDF/格式降级、跨保险库拼接成功。
- 中：需要本地特权或复杂交互的秘密残留、拒绝服务、错误清理非目标应用数据。
- 低：不暴露秘密且有明确绕过条件的安全提示、加固或元数据问题。

最终分级结合可利用性、权限、用户交互、数据机密性/完整性和恢复难度。

## 5. 披露原则

- 修复或有效缓解前不公开可直接利用细节。
- 不承诺对未修复问题保密无限期；与报告者协商合理期限。
- 公告说明受影响版本、修复版本、数据格式影响、检测与恢复步骤。
- 公开内容不得包含报告者不愿公开的身份或任何用户数据。
- 不把哈希、混淆或“仅本地”描述为漏洞不存在的理由。

## 6. 当前限制

M3 尚未获得独立安全评审、正式代码签名和公开发布批准。当前构建只允许虚构测试数据；发现问题时优先停止候选，而不是建议用户继续保存真实秘密。
