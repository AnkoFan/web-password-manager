# 第二阶段安全回归评审

> 评审日期：2026-07-30
>
> 结论：M2.5 内部安全与恢复闭环通过，M2.6 首批加固通过；仍不批准保存真实秘密或公开发布。

## 本次关闭

- SR-006：剪贴板定时且有条件清理已实现，生产定时任务只保留内容摘要。
- SR-007：Rust 空闲计时、窗口失焦锁定和前端锁定事件清理已实现。
- SR-008：加密备份、摘要清单、密码/数据库完整性验证、恢复回滚和演练已实现。
- 前端直接写剪贴板权限已移除；网址在 Rust 端验证后才交给系统打开。
- SR-004：SQLCipher `cipher_memory_security` 已启用并读回验证；Windows 构建关闭 OS 页锁定，保留全分配器内存擦除。
- SR-013：已建立提交 `958a40e` 和 `m2.5-internal` 标签，提交级追溯恢复。

## 仍未关闭

- SR-005：数据库截断、数据库页、包装 DEK 和异常 KDF 参数篡改已覆盖；密码学已知向量及盐、nonce、标签和头库错配矩阵尚未补齐。
- SR-009：安全头格式与 KDF 参数升级机制尚未完成。
- SR-010：WebView 缓存、崩溃数据和 IPC 专项扫描仍不完整。
- SR-012：RustSec 锁文件审计尚未进入自动化。

## 新增限制

- 同机备份不抵御整盘故障或设备丢失。
- 安全头与数据库为双文件，恢复替换不能做到单文件级原子提交；代码使用暂存验证和回滚副本降低风险。
- Windows 锁屏、切换和休眠由窗口失焦安全策略覆盖；原生 WTS/电源广播的自动化注入测试仍待补充。
- 失去焦点立即锁定是保守策略，可能比用户预期更频繁。
- 当前 Windows SQLCipher 策略擦除 SQLite/SQLCipher 分配器释放的内存，但不使用 `VirtualLock`，因此不能声称敏感页不会被系统换出。

## 判定

M2.1–M2.5 的内部开发目标可以标记完成，M2.6 首批加固验收通过。SR-005、SR-009、SR-010、SR-012 以及独立安全评审未关闭前，不得移除“仅使用虚构测试数据”的限制。
