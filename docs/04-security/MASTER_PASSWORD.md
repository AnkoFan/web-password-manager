# 主密码策略

> 用途说明：定义主密码的创建、验证、传递、修改、遗忘和测试规则。
>
> 状态：第一阶段策略已实现 / 修改密码流程待设计
>
> 最后更新日期：2026-07-30

## 1. 目标

主密码是用户解锁本地保险库的唯一知识因素。软件不保存主密码，不提供云端重置，也不能承诺在忘记主密码后恢复数据。

## 2. 创建规则

- 最少 12 个 Unicode 字符。
- 界面建议使用多个无关词语组成的长密码。
- 必须输入两次并完全一致。
- 用户必须确认理解“忘记后可能无法恢复数据”。
- 不强制大小写、数字和特殊字符组合，避免诱导短而难记的密码。
- 不设置最大长度作为普通产品限制；实现层需防止极端输入造成资源滥用。

## 3. 处理边界

- 输入框使用密码类型，用户可主动临时显示。
- 不写入 localStorage、sessionStorage、URL、剪贴板、日志或崩溃报告。
- React 只在提交所需的最短时间内持有输入值。
- 主密码通过单一 Tauri 命令发送到 Rust。
- Rust 派生 KEK 后使用 `zeroize` 清理接收字符串。
- 主密码不直接作为 SQLCipher 密钥。

## 4. 验证

- Argon2id 根据安全头参数派生 KEK。
- KEK 解包随机 DEK。
- 解包失败返回统一错误，不区分密码错误、包装数据错误或部分头损坏。
- DEK 打开 SQLCipher 后继续验证数据库标记。
- 成功后建立进程内解锁会话；主密码和 KEK不保留。

## 5. 错误处理

- 错误提示固定为“主密码不正确，请重新输入”或同等通用文案。
- 不显示 KDF、AEAD、SQLCipher 或数据库内部错误。
- 不清空整个页面，保留输入焦点供用户重试。
- 第一版不设计账号锁定或联网限速；后续评估本地渐进延迟，不能造成拒绝服务风险。

## 6. 忘记主密码

- 不设置密保问题、默认后门、通用恢复码或远程重置。
- 帮助页面明确说明软件无法代替用户解密。
- 如果用户有旧备份，只能使用保护该备份的旧主密码恢复。
- 删除旧保险库并新建属于破坏性操作，必须明确选择文件和确认数据不可恢复。

## 7. 修改主密码

后续实现必须：

1. 在已解锁状态验证当前主密码。
2. 生成新盐和新 KDF 参数记录。
3. 从新主密码派生新 KEK。
4. 使用新随机 nonce 重新包装同一 DEK。
5. 原子替换安全头并验证新密码。
6. 不重写全部数据库。

旧备份仍由旧主密码保护，界面必须提醒用户。

## 8. 测试

- [ ] 11 个字符被拒绝，12 个字符被接受
- [ ] 两次输入不一致被拒绝
- [ ] 错误主密码不能解包 DEK
- [ ] 正确主密码在重启后可以解锁
- [ ] 日志、DOM 属性和持久化存储不出现主密码
- [ ] 锁定后数据库连接和敏感前端状态被清理
- [ ] 超长输入具有安全、明确的上限或资源保护
- [ ] 修改主密码不会改变 DEK
