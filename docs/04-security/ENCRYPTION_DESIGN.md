# 加密设计

> 用途说明：定义主密码派生、随机数据密钥、密钥包装、数据库加密、文件格式、密钥生命周期、参数升级和密码修改方案。
>
> 状态：分层密钥与安全头 v2 设计已冻结 / 待独立密码学评审
>
> 最后更新日期：2026-07-31

## 1. 设计摘要

采用分层密钥设计：

```text
主密码
  │
  ├─ Argon2id + 随机盐 + 可版本化参数
  ▼
密钥加密密钥（KEK）
  │
  ├─ AEAD 解包
  ▼
随机数据加密密钥（DEK）
  │
  └─ 作为加密数据库的原始密钥
```

主密码不直接加密每条账号数据。随机 DEK 负责数据库，主密码派生出的 KEK 只负责包装 DEK。

### 1.1 当前实现与 M3 目标

当前原型采用：

- Argon2id 1.3，64 MiB、3 次迭代、并行度 1，输出 32 字节 KEK。
- 16 字节随机盐。
- 32 字节随机 DEK。
- XChaCha20-Poly1305 包装 DEK，24 字节随机 nonce。
- 安全头核心字段作为 AEAD 关联数据。
- DEK 作为 SQLCipher 原始密钥。
- Rust `zeroize` 清理主密码、KEK、DEK 与复制过程中的临时敏感字符串。

M3 保持这些算法并迁移到带 magic、vault ID、规范 AAD 和已知 KDF 配置注册表的安全头 v2。完整格式和提交协议见 [ADR-012](../00-foundation/10-ADR_VAULT_HEADER_V2.md)。这不等同于独立密码学评审完成。

优点：

- 修改主密码只需重新包装 DEK。
- 数据库加密与主密码策略解耦。
- KDF 参数可以升级。
- 备份可以保留完整自包含格式。

## 2. 算法选择

### 2.1 密钥派生

- 算法：Argon2id 1.3。
- 输出：32 字节 KEK。
- 盐：每个保险库随机 16 字节。
- 初始候选参数：64 MiB 内存、3 次迭代、并行度根据库和目标设备评测确定。
- 目标：在最低支持设备上解锁延迟大致处于 250–750 毫秒区间。
- 参数下限不得低于项目安全评审时采用的 OWASP 基线。
- 参数保存在安全头中，允许以后升级。

RFC 9106 将 Argon2id 64 MiB、3 次迭代列为内存受限环境的推荐选项。最终参数必须在实际 Windows 设备上测量，不能只复制文档值。

### 2.2 数据密钥

- 256 位随机 DEK。
- 使用操作系统支持的密码学安全随机源，经语言标准安全随机接口调用。
- 不从主密码、时间、设备标识或普通随机数生成器推导。

### 2.3 密钥包装

已接受选择：

- XChaCha20-Poly1305。
- 192 位随机 nonce。
- 认证标签由维护中的 RustCrypto 实现生成和验证。
- 安全头中的版本、KDF 参数、盐和包装算法作为关联数据。

算法和格式语义已在 ADR-012 冻结；仍需完成依赖审查和独立安全评审。不得自行实现 AEAD。

### 2.4 数据库加密

已接受实现：SQLCipher。

- 使用 256 位原始 DEK 打开数据库，避免 SQLCipher 再次直接处理用户主密码。
- 采用 SQLCipher 当前受支持格式和完整性保护。
- 明确设置兼容版本和安全参数，不能依赖不同版本可能变化的隐式默认值。
- 启用数据库完整性和密钥验证测试。

SQLCipher 具体页面算法和参数以选定版本的官方设计文档为准。技术原型必须先验证 Windows 构建、备份、迁移和单一安装包兼容性。

## 3. 保险库文件布局

建议将一个保险库表现为应用管理的目录或单一容器。逻辑内容：

```text
Vault
├─ header
│  ├─ magic
│  ├─ containerVersion
│  ├─ vaultId
│  ├─ kdfAlgorithm
│  ├─ kdfParameters
│  ├─ salt
│  ├─ wrapAlgorithm
│  ├─ wrapNonce
│  └─ wrappedDekWithTag
└─ encryptedDatabase
```

如果选择目录形式，安全头和加密数据库必须作为一个逻辑整体进行备份、迁移和替换。最终也可以设计单文件容器，但不能为追求“一个文件”牺牲事务安全。

## 4. 安全头

允许明文存在但必须被认证绑定：

- 文件魔数。
- 容器格式版本。
- KDF 算法和参数。
- 随机盐。
- 密钥包装算法。
- 包装 nonce。
- 随机保险库标识。

禁止明文存在：

- 账号数据。
- 分类、网站和用户名。
- 主密码验证提示。
- 明文 DEK 或 KEK。
- 用户可识别的保险库内容摘要。

安全头中会影响解密解释的字段必须进入 AEAD 关联数据，防止参数替换和降级。

## 5. 创建保险库

1. 验证主密码和确认输入。
2. 从操作系统安全随机源生成 16 字节盐。
3. 生成 32 字节随机 DEK。
4. 使用 Argon2id 从主密码和盐派生 32 字节 KEK。
5. 生成随机包装 nonce。
6. 用 KEK 和 AEAD 包装 DEK，并绑定安全头关键字段。
7. 使用 DEK 初始化加密数据库。
8. 创建数据库结构和随机验证标记。
9. 在临时位置完成全部写入和完整性验证。
10. 原子移动为有效保险库。
11. 清理主密码、KEK、DEK 临时副本和失败文件。

任一步失败都不能留下被识别为有效的空保险库。

## 6. 解锁

1. 读取并限制安全头大小。
2. 验证魔数、版本、算法标识和参数范围。
3. 使用头中的盐和参数从主密码派生 KEK。
4. 使用 AEAD 解包 DEK。
5. 解包失败时返回统一解锁失败，不打开数据库。
6. 使用 DEK 打开 SQLCipher 数据库。
7. 验证数据库完整性、结构版本和验证标记。
8. 成功后建立解锁会话。
9. 清理主密码和 KEK。
10. DEK 只在解锁会话中保留。

不单独保存快速主密码哈希。AEAD 解包结果和数据库验证已经提供正确性判断；额外快速验证器可能降低离线猜测成本。

## 7. 锁定

- 停止新数据库操作。
- 完成或取消正在进行的事务。
- 关闭数据库连接。
- 清空搜索、详情和编辑状态。
- 清理 DEK 和解密缓存。
- 返回锁定界面。

语言运行时可能复制字符串，无法保证所有内存物理字节立即消失；实现应减少副本并使用可清零敏感缓冲区。

## 8. 修改主密码

1. 保险库必须已解锁。
2. 重新验证当前主密码或当前解锁凭据。
3. 输入并确认新主密码。
4. 生成新盐和新 KDF 参数记录。
5. 派生新 KEK。
6. 使用新随机 nonce 重新包装同一 DEK。
7. 原子替换安全头。
8. 验证新主密码可以解包。
9. 清理旧 KEK 和临时头。

修改主密码不自动改变旧备份。界面必须提醒旧备份仍由旧主密码保护。

## 9. KDF 参数升级

解锁后如果检测到旧参数：

- 提示或后台安全升级。
- 使用当前主密码派生新 KEK。
- 使用新盐和参数重新包装同一 DEK。
- 原子更新安全头。
- 不重写全部数据库。

不允许仅修改参数字段而不重新包装 DEK。

## 10. 数据密钥轮换

DEK 轮换与修改主密码不同：

- 修改主密码：只重新包装同一 DEK。
- 轮换 DEK：数据库使用新密钥重新加密。

DEK 轮换属于高风险维护操作，只有在算法迁移、疑似密钥泄露或格式升级需要时执行。必须先创建可恢复备份并验证新数据库。

## 11. 备份

加密备份包含：

- 完整安全头。
- 完整加密数据库。
- 恢复所需版本信息。

复制过程：

- 在数据库一致性快照上进行。
- 不解密为中间文件。
- 复制后校验长度、哈希和数据库可解锁性。
- 不把备份哈希当作密码学保密措施。

## 12. 随机数

随机数用于：

- DEK。
- KDF 盐。
- AEAD nonce。
- 保险库和实体标识。

要求：

- 使用操作系统或成熟密码库提供的 CSPRNG。
- 检测随机源失败并停止创建或加密。
- 不使用时间戳、进程 ID、Math.random 或可预测种子。
- nonce 长度和唯一性遵循所选 AEAD 要求。

## 13. 密钥内存管理

- 主密码使用敏感输入类型，不进入通用状态管理或前端持久化。
- KEK 只存在于派生、解包或重新包装期间。
- DEK 只存在于解锁会话。
- 密钥不能实现普通调试打印、克隆或序列化。
- Rust 侧优先使用 `secrecy`、`zeroize` 或等价受维护机制，最终依赖需审查。
- 不通过前端 IPC 返回 DEK、KEK 或完整数据库密钥。
- 锁定和异常路径都执行清理。

## 14. 前端与后端边界

如果采用 Tauri：

- 主密码可以由前端输入，但立即通过受限命令传给 Rust 安全模块。
- 前端不得保存主密码到 localStorage、sessionStorage、URL、日志或全局状态持久化。
- DEK 和 KEK永不进入 WebView。
- Rust 后端返回成功、失败和最小数据视图。
- 敏感字段值仅在用户查看或复制所需时返回，避免一次返回整个保险库。

## 15. 算法敏捷性

格式必须记录：

- 容器版本。
- KDF 标识和参数。
- 包装算法标识。
- 数据库格式兼容版本。

读取未知算法：

- 不猜测。
- 不降级。
- 默认拒绝写入。
- 提示使用支持该格式的应用版本。

算法迁移使用新容器或安全头版本，并保留恢复路径。

## 16. 不采用的设计

- 主密码直接作为数据库密码。
- SHA-256 等快速哈希直接派生密钥。
- 固定盐或固定 nonce。
- 把密钥写死在程序中。
- 用设备序列号、Windows 用户名或 MAC 地址当密钥。
- 只加密密码列而让网站、用户名和字段标签明文保存。
- 仅靠文件扩展名或格式混淆。
- 自行设计流密码、认证码或密钥包装算法。
- 把 DPAPI 作为唯一解锁机制。

## 17. 测试要求

### 17.1 已知向量

- Argon2id 使用官方或库提供的测试向量。
- AEAD 使用标准测试向量。
- SQLCipher 使用选定版本兼容性和完整性测试。

### 17.2 错误与篡改

- 错误主密码。
- 修改盐、KDF 参数或算法标识。
- 修改包装 nonce、密文 DEK 或认证标签。
- 修改数据库任意页面。
- 截断安全头或数据库。
- 用其他保险库的头与数据库拼接。

以上均不得返回部分业务数据。

### 17.3 生命周期

- 创建中断。
- 解锁后锁定。
- 修改主密码中断。
- KDF 参数升级中断。
- 备份和恢复失败。
- 数据库重加密失败。

### 17.4 性能

- 在最低支持 Windows 设备测量 Argon2id。
- 记录内存峰值、解锁耗时和并发行为。
- 参数过高造成内存分配失败时安全失败，不降低到未记录的弱参数。

- [ ] 算法和库版本已确定。

- [ ] 安全头关联数据定义明确。

- [ ] SQLCipher 原始密钥配置经过验证。

- [ ] 格式和实现经过独立代码审查。
