# 保险库锁定

> 用途说明：定义锁定状态、当前实现、命令门控、界面清理和后续自动锁定要求。
>
> 状态：M3 原生 Windows 会话/电源监听已实现，真实系统人工验收待完成
>
> 最后更新日期：2026-07-31

## 1. 安全目标

- 锁定后关闭 SQLCipher 连接，不以隐藏界面代替锁定。
- 锁定状态下拒绝显示、复制和后续业务命令。
- 清除当前详情、搜索结果、编辑草稿和敏感字段显示状态。
- 应用重启后始终从锁定状态开始。
- 锁定失败时不继续显示为已安全锁定。

## 2. 当前状态机

```text
loading → setup
loading → locked
loading → recovery
setup  → unlocked
locked → unlocked
unlocked → locked
```

Rust `VaultSession` 只保存一个可选 SQLCipher `Connection`。连接不存在即为锁定；`lock_vault` 通过 `take()` 丢弃连接。应用进程不会持久化“已解锁”标记。

M2.5 增加最后活动时间和安全设置。Rust 后台监控每秒检查一次空闲时间，默认 5 分钟、允许 1–60 分钟。业务命令和前端节流后的键盘、指针、焦点活动会刷新时间。

桌面窗口失去焦点时默认立即锁定，用于覆盖切换应用。M3 另行注册当前会话的 WTS 通知和 Windows 电源广播；锁屏、注销、会话断开、进入挂起和自动恢复都会触发 Rust 会话锁定。唤醒或重新聚焦不会自动解锁。

前端启动调用 `vault_status`：

- 安全头和数据库都不存在：进入创建。
- 两者都存在：进入锁定。
- 只存在其中一个：进入恢复错误，禁止创建和编辑。

## 3. 命令边界

当前读取秘密的命令必须先通过 `require_connection`。锁定后返回统一的“保险库已锁定”错误。

第二阶段新增命令必须遵守同一规则：

- 列表、搜索、详情、保存、删除、恢复、显示和复制全部检查 Rust 会话。
- 不只依赖 React 路由或按钮状态。
- 不把连接、DEK、KEK 或整库对象返回 WebView。

## 6. 自动锁定要求

第二阶段实现时：

- 计时器只触发锁定请求，最终状态由 Rust 会话决定。
- 用户输入、复制和保存等活动如何重置计时器必须一致。
- 系统休眠或会话锁定优先立即锁定。
- 唤醒后不得自动恢复解锁状态。
- 自动锁定不得静默丢弃已确认写入；未保存草稿的处理必须明确。
- 自动锁定默认值和允许范围需通过独立决策确定。
