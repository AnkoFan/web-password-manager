# 保险库无锁定边界

> 用途说明：记录当前产品为何不提供锁定/解锁，以及自动打开模型下仍需遵守的安全边界。
>
> 状态：ADR-014 现行决定 / M3 已验证
>
> 最后更新日期：2026-08-02

## 1. 当前行为

- 应用启动时验证 SQLCipher 数据库与 DPAPI 密钥文件必须成对存在。
- 首次启动由 Rust 生成随机 256 位 SQLCipher 密钥，并用当前 Windows 用户 DPAPI 保护。
- 后续启动自动由 DPAPI 解开密钥并打开数据库，直接进入主界面。
- 产品没有主密码、锁定、解锁、自动锁定、生物识别或锁屏联动入口。
- 失焦、最小化、休眠、锁屏和切换 Windows 用户不会触发应用内部锁定状态。

## 2. 安全失败边界

以下情况必须在任何业务写入前安全停止：

- 数据库或 DPAPI 密钥文件只存在一个。
- DPAPI 文件格式非法、被篡改或不属于当前 Windows 用户。
- SQLCipher 数据库无法通过密钥验证、完整性检查或保险库标记检查。
- 数据库 schema 高于当前支持版本。
- 恢复操作无法同时验证数据库、密钥文件和完整性清单。

失败时不得把现有数据当作空保险库，不得创建或覆盖缺失文件，也不得把系统错误细节或密钥材料返回界面。

## 3. 运行期保护

- 密码等敏感字段默认隐藏，只有明确用户操作才能显示或复制。
- 切换对象、重新挂载组件或重启应用后，敏感字段恢复隐藏。
- 复制内容只在仍匹配应用写入值时执行条件超时清理；Windows 剪贴板历史不受此保证。
- 数据库密钥只在 Rust/SQLCipher 所需范围内处理，不返回前端、不写入日志。
- 应用退出时关闭数据库连接并释放运行期状态。

## 4. 明确残余风险

静态加密不解决以下风险：

- 当前 Windows 用户上下文中的恶意程序或管理员权限读取。
- 应用运行期间的内存读取、屏幕捕获、肩窥和键盘记录。
- 用户主动显示或复制后的剪贴板历史与第三方工具保留。
- DPAPI 备份跨 Windows 用户或跨设备恢复。

界面和发布说明必须准确披露这些边界，不能把“自动打开”描述成存在隐藏锁定层。

## 5. 验收

- [x] 启动和重启直接进入主界面，不出现锁定或解锁页面。
- [x] 生产源码、命令和界面中不存在锁定/解锁能力。
- [x] DPAPI 往返、篡改拒绝、文件对不完整拒绝和 SQLCipher 非明文文件头测试通过。
- [x] 休眠、锁屏和切换用户不会触发应用锁定。
- [x] 设置页说明 DPAPI 自动加密与跨用户/跨设备恢复限制。
- [x] 敏感字段默认隐藏，显示和复制需要明确用户操作。
