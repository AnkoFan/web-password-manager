# 第一阶段安全代码与文档评审

> 评审日期：2026-07-30
>
> 范围：0.1.0 本地安全技术原型及第二阶段迁移准备
>
> 结论：第一阶段内部评审完成；不批准保存真实秘密或公开发布

> 后续状态：本文保留第一阶段发现的历史基线；SR-004–SR-008、SR-010–SR-013 的开发范围已在 M2.6 关闭，当前结论以[第二阶段安全回归](PHASE_2_SECURITY_REVIEW.md)为准。

## 1. 评审范围

- Rust：密钥派生、DEK 包装、SQLCipher 打开、文件创建、解锁、锁定、复制命令和 Tauri 注册。
- 前端：主密码输入、会话状态、秘密显示/复制客户端和浏览器开发模拟。
- 配置：Tauri CSP、窗口能力、剪贴板和网址打开权限。
- 文档：安全模型、威胁模型、加密设计、锁定和敏感数据处理。
- 依赖：npm 审计、Rust 直接依赖版本和 RustSec 公开记录人工核对。

本评审是项目内部实现评审，不是独立密码学审计、渗透测试或第三方安全认证。

## 2. 已确认控制

- Argon2id 1.3，64 MiB、3 次迭代、并行度 1，随机 16 字节盐。
- 随机 32 字节 DEK；XChaCha20-Poly1305 使用随机 24 字节 nonce 包装。
- 版本、KDF、盐和包装算法绑定为 AEAD 关联数据。
- KEK、DEK 和 Rust 命令主密码使用 `zeroize` 容器或显式清理。
- SQLCipher 使用原始 DEK；数据库文件头不是明文 SQLite。
- 解锁执行 SQLCipher 页面 HMAC、SQLite 逻辑完整性和保险库标记检查。
- 安全头读取限制为 64 KiB。
- 创建中间文件不会被识别为有效保险库；部分文件状态进入恢复流程。
- 锁定关闭数据库连接；秘密读取命令在 Rust 侧再次检查会话。
- 前端未使用 Web Storage、危险 HTML 注入或远程数据请求。
- Tauri CSP 和 capability 范围较小，网址打开当前只允许虚构测试地址。
- `npm audit` 对生产和全部依赖均报告 0 个已知漏洞。

## 3. 本次已修复

### SR-001 超大安全头无读取上限

- 原等级：高。
- 风险：本地畸形头文件可造成无界内存分配或解析资源消耗。
- 处理：读取前检查文件大小，空文件或超过 64 KiB 时拒绝。
- 证据：`oversized_header_is_rejected_before_parsing`。

### SR-002 解锁只验证标记，未遍历页面完整性

- 原等级：高。
- 风险：未被正常查询触及的损坏页面可能在解锁时未被发现。
- 处理：增加 `PRAGMA cipher_integrity_check` 和 `PRAGMA integrity_check`。
- 证据：`unlock_rejects_tampered_database`。

### SR-003 重启解锁只有代码路径，没有跨进程验收

- 原等级：高。
- 风险：连接关闭后文件、头信息或参数不兼容可能直到实际重启才暴露。
- 处理：新增独立子进程错误密码与正确密码验收。
- 证据：`persisted_vault_unlocks_in_independent_processes`。

## 4. 未关闭发现

### SR-004 SQLCipher 增强内存安全在 Windows 不可用

- 等级：高，公开使用阻断。
- 现象：`cipher_memory_security = ON` 在完整结构初始化时出现 `VirtualLock` 错误 1453 并导致栈溢出。
- 当前处理：保持 SQLCipher 默认关闭，避免应用崩溃；Rust 自有密钥缓冲区继续零化。
- 后续：评估工作集配额、SQLCipher 版本行为、失败策略和替代锁页方案。
- M2.6 后续状态：已通过 `OMIT_MEMLOCK` 安全构建启用全分配器擦除并验证状态；OS 页锁定仍未提供，详见[第二阶段安全回归](PHASE_2_SECURITY_REVIEW.md)。

### SR-005 缺少标准密码学已知向量与完整篡改矩阵

- 等级：高，公开使用阻断。
- 当前只有确定性、往返、错误密码、数据库单字节篡改测试。
- 后续：加入 Argon2id、XChaCha20-Poly1305 官方/上游向量；覆盖盐、参数、nonce、包装密文、标签、截断和头库错配。
- M2.6 后续状态：RFC 9106 Argon2id、IETF XChaCha20-Poly1305 草案向量及完整篡改矩阵已经通过。

### SR-006 剪贴板内容没有定时且有条件清理

- 等级：高，公开使用阻断。
- 当前复制后由 Windows 和第三方工具决定生命周期。
- 后续：保存本次写入的安全摘要或等价标识，超时前确认剪贴板仍属于本次写入，再清除。
- M2.5 后续状态：已实现 SHA-256 摘要匹配后的定时条件清理；Windows 剪贴板历史仍列入 M3 人工验收。

### SR-007 没有自动锁定和休眠锁定

- 等级：高，公开使用阻断。
- 当前只有手动锁定和进程重启锁定。
- 后续：实现空闲、休眠、Windows 会话锁定和唤醒保持锁定。
- M2.5 后续状态：空闲计时、窗口失焦锁定和前端锁定事件清理已实现；真实系统事件注入转入 M3 人工验收。

### SR-008 没有加密备份恢复演练

- 等级：高，公开使用阻断。
- 当前双文件保险库没有一致性快照、独立目录恢复和失败回滚验证。
- M2.5 后续状态：加密备份、摘要清单、密码与数据库验证、恢复回滚和损坏备份拒绝已经通过。

### SR-009 安全头格式与参数升级能力未完成

- 等级：中。
- 当前头缺少明确 magic 和 vault ID，并要求 KDF 参数与当前常量完全相同；不支持安全参数升级。
- 后续：冻结容器格式、范围校验、头库绑定和原子头更新方案。

### SR-010 WebView 和 IPC 专项测试不足

- 等级：中。
- CSP 和 capability 已最小化，但没有自动验证命令白名单、CSP 回归、WebView 存储/崩溃文件秘密扫描。

### SR-011 固定演示秘密仍包含在生产前端和数据库初始化

- 等级：中，接入真实数据前阻断。
- 内容为虚构数据，不构成当前秘密泄露；但演示读取路径会混淆正式数据边界。
- 后续：M2.3 接入业务仓储时删除 `demo_fields`、演示秘密和相关命令。
- 第二阶段复核：已在迁移 002、真实业务命令与数据管理界面中完成移除，SR-011 于 M2.4 关闭。

### SR-012 Rust 漏洞审计未自动化

- 等级：中。
- `cargo-audit` 未安装；本次只人工核对直接关键依赖及 RustSec 页面。
- 已确认当前 `rusqlite 0.40.1` 不在历史 `rusqlite` 公告的受影响版本范围；仍需在 CI 中运行完整锁文件审计。
- M2.6 后续状态：GitHub Actions RustSec `audit-check` 已运行并通过。

### SR-013 源码目录没有 Git 元数据

- 等级：中，供应链和审计阻断。
- 无法确认源码提交、评审差异和产物之间的可追溯关系。
- 后续：恢复原仓库历史或在确认来源后初始化仓库，随后建立签名提交/发布记录。
- M2.6 后续状态：Git、私有 GitHub 仓库、正式 noreply 提交身份及内部验收标签已经建立。
