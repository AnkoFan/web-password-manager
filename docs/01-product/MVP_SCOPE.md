# MVP 范围

> 用途说明：锁定内部 MVP 必须实现的最小功能、明确排除项、交付物和退出标准，防止开发范围失控。
>
> 状态：历史内部 MVP 范围 / 不再作为当前验收标准
>
> 最后更新日期：2026-07-30

> 现行说明：本文保留早期主密码和锁定方案的需求记录。当前产品以 ADR-014、M3 完成记录和 M4 执行计划为准，不实现本文中的主密码、锁定或解锁条目。

## 1. MVP 定义

本项目的 MVP 是一个仅用于验证核心产品闭环的内部版本：

```text
创建保险库
→ 保存分类、网站和多个账号
→ 添加自定义字段
→ 关闭并重新打开
→ 解锁、搜索、复制和打开网址
→ 再次锁定
```

MVP 不等于安全成熟的正式密码管理器，也不等于可直接向公众发布的版本。威胁模型、加密实现、安全测试、备份恢复和发布检查完成前，MVP 只能使用虚构测试数据，不能保存真实密码、令牌、私钥或恢复码。

## 2. MVP 要回答的问题

MVP 应验证：

- “分类 → 网站 → 多账号”的组织方式是否容易理解。
- 同一个网站下管理多个账号是否比重复创建网站更清晰。
- 基础字段加自定义字段是否能够覆盖主要信息类型。
- 搜索、复制和打开网址能否形成高效日常流程。
- 模块化架构能否在不增加过多界面层级的情况下工作。
- 本地数据能否在关闭、重启、解锁后保持一致。

MVP 不用于证明：

- 产品已经达到公开安全使用标准。
- 所有攻击场景都已被处理。
- 跨平台、云同步或浏览器集成已经可行。
- 动态插件系统是必要的。

## 3. 范围状态定义

| 标记 | 含义 |
| --- | --- |
| 必须 | 缺失时 MVP 不成立 |
| 可简化 | 必须存在，但实现可以采用最小方案 |
| 延后 | 不进入 MVP，首个公开版本或以后再评估 |
| 禁止 | MVP 中不得以临时不安全方式实现 |

## 4. MVP 必须实现

### 4.1 保险库

- [ ] 首次启动可以创建一个本地保险库。
- [ ] 用户必须输入并确认主密码。
- [ ] 两次主密码不一致时不能创建。
- [ ] 正确主密码可以解锁。
- [ ] 错误主密码不能解锁。
- [ ] 用户可以手动锁定。
- [ ] 锁定后界面不得继续显示或复制保险库内容。
- [ ] 正常关闭并重新打开后，已保存数据仍可读取。
- [ ] 正式持久化文件不得直接保存可读明文秘密。

### 4.2 分类

- [ ] 新建分类。
- [ ] 查看分类列表。
- [ ] 重命名分类。
- [ ] 删除空分类。
- [ ] 删除非空分类时明确提示受影响内容，不允许静默级联删除。

### 4.3 网站

- [ ] 在分类下新建网站。
- [ ] 保存网站名称和主网址。
- [ ] 查看并编辑网站。
- [ ] 删除网站前显示其账号影响并要求确认。
- [ ] 使用系统默认浏览器打开有效网址。
- [ ] 无效或不受支持的网址不能被静默打开。

### 4.4 多账号

- [ ] 同一网站下可以添加至少两个账号。
- [ ] 每个账号具有可区分用途的账号名称。
- [ ] 查看和切换同一网站下的账号。
- [ ] 编辑账号而不影响其他账号。
- [ ] 删除单个账号而不影响同网站的其他账号。

### 4.5 字段

- [ ] 账号至少可以保存账号名称、用户名、密码和备注。
- [ ] 密码默认隐藏。
- [ ] 可以临时显示或再次隐藏密码。
- [ ] 可以创建多个自定义字段。
- [ ] 自定义字段包含名称、值、排序和敏感属性。
- [ ] 可以编辑、排序和删除自定义字段。
- [ ] 敏感自定义字段默认隐藏。

### 4.6 搜索

- [ ] 提供全局搜索入口。
- [ ] 至少可以搜索网站名称、账号名称和用户名。
- [ ] 结果能显示所属分类、网站和账号等区分信息。
- [ ] 可以从搜索结果进入对应详情。
- [ ] MVP 不为密码、Token 等秘密创建明文持久化索引。

### 4.7 复制与网址

- [ ] 可以复制用户名。
- [ ] 可以复制密码。
- [ ] 可以复制网站网址。
- [ ] 可以复制自定义字段。
- [ ] 复制反馈不显示被复制值。
- [ ] 打开网址与复制网址是独立操作。

### 4.8 界面与反馈

- [ ] 解锁、分类、网站、账号和搜索具有清晰界面边界。
- [ ] 新保险库、空分类、无账号和无搜索结果有空状态。
- [ ] 保存成功、保存失败、复制成功和删除失败有明确反馈。
- [ ] 危险删除操作与普通操作可以明显区分。
- [ ] 高频流程不应为了体现模块化而增加无必要页面。

### 4.9 数据正确性

- [ ] 实体使用稳定内部标识，不只依赖显示名称。
- [ ] 关键写入失败时不得提示成功。
- [ ] 删除和更新操作不得影响无关对象。
- [ ] 应用正常重启后对象关系、字段顺序和敏感属性保持一致。
- [ ] 应用异常退出的基础风险必须被测试和记录。

## 5. MVP 可采用的简化方案

- 只支持一个保险库。
- 只支持 Windows。
- 只提供一种完整、可用的界面主题。
- 分类使用固定排序或按名称排序。
- 网站使用统一默认图标，不联网抓取 Favicon。
- 搜索采用简单的本地包含匹配。
- 字段值可以先统一保存为文本，但必须保留敏感属性。
- 收藏和标签可以不进入 MVP。
- 已实现手动、空闲和窗口失焦锁定；公开版本前继续补原生系统事件注入测试。
- 已实现剪贴板定时条件清除，并在界面和安全文档中说明限制。
- 模块使用编译期注册，不实现动态插件安装。

简化不能违反以下底线：

- 不得用明文 JSON、CSV 或文本文件代替正式保险库存储。
- 不得保存主密码。
- 不得使用固定密钥、默认密钥或写死的测试密钥构建正式 MVP。
- 不得把密码或 Token 写入日志。
- 不得用关闭界面显示代替真正的锁定状态。

## 6. 明确不进入 MVP

### 6.1 进入首个公开版本前完成

- [x] 自动锁定。
- [x] 剪贴板定时清除及限制说明。
- [x] 本机加密备份和恢复。
- 数据版本和迁移机制。
- 完整威胁模型及安全测试。
- 数据损坏、错误密码和不兼容版本的完善处理。
- 安装包、升级、恢复和发布检查。
- 开源许可证及安全漏洞报告流程。

### 6.2 后续候选

- 收藏和标签。
- 密码生成器。
- 字段模板和网站模板。
- 导入导出。
- 多保险库。
- 附件。
- 深色主题和自定义主题。
- macOS 和 Linux。
- 动态插件。

### 6.3 当前明确排除

- 云同步。
- 团队共享和企业权限。
- 浏览器扩展与自动填充。
- 移动应用。
- 在线管理后台。
- 生物识别、硬件安全密钥和远程擦除。

## 7. MVP 交付物

MVP 完成时必须同时具备：

### 7.1 软件

- 可以在选定的 Windows 开发环境中启动。
- 可以完成全部 MVP 核心流程。
- 模块边界符合架构文档，不把所有逻辑集中在单个页面。

### 7.2 数据与安全设计

- 初版数据模型和数据库结构。
- 初版威胁模型和加密设计。
- 主密码、锁定和敏感数据处理说明。
- 明确声明 MVP 只能使用虚构数据，直到安全发布门槛达成。

### 7.3 测试

- P0 功能的单元测试和必要集成测试。
- 至少一条完整端到端测试。
- 关闭重启、错误密码、删除影响和保存失败测试。
- 不使用真实秘密的测试数据。

### 7.4 文档

- MVP 使用说明。
- 开发环境搭建说明。
- 项目结构和模块开发说明。
- 已知限制及未完成功能。

## 10. 范围变更规则

新增功能只有满足以下条件才能进入 MVP：

1. 不实现它就无法验证核心产品闭环；或
2. 不实现它会导致明显的数据安全或数据丢失风险。

任何新增项必须同时：

- 标明对应 PRD 编号。
- 标明所属模块。
- 提供验收标准。
- 说明对里程碑的影响。
- 说明是否导致其他功能退出 MVP。

“以后可能会需要”不能单独作为进入 MVP 的理由。
