# 功能清单

> 用途说明：集中管理功能编号、优先级、目标阶段、所属模块、当前状态和关键依赖，作为路线图与开发任务的索引。
>
> 状态：现行功能索引 / M3、M4 已完成 / M5.0–M5.4 已完成
>
> 最后更新日期：2026-08-03

## 1. 使用规则

- 本清单记录产品功能，不代替详细 PRD。
- 功能进入开发前必须具有明确编号、模块、优先级和验收标准。
- 目标阶段分为“内部 MVP”“公开 V1”“后续候选”和“当前排除”。
- 尚未决定是否进入某阶段的功能标记为“待决策”，不能视为承诺。
- 已通过 M3 验收的功能标记为“已完成”；被 ADR-014 取消的主密码和锁定能力标记为“排除”。

## 2. 优先级

| 优先级 | 含义 |
| --- | --- |
| P0 | 内部 MVP 核心闭环必须实现 |
| P1 | 首个公开版本必须实现 |
| P2 | 有价值的版本候选，是否进入 V1 待评审 |
| P3 | 长期候选，不进入当前开发计划 |
| — | 当前明确排除或不适用 |

## 3. 状态

| 状态 | 含义 |
| --- | --- |
| 已定义 | 已在 PRD 中形成初步需求 |
| 待决策 | 版本、规则或方案尚未确定 |
| 待设计 | 需求明确，等待数据、界面或架构设计 |
| 待开发 | 设计完成后可以进入实现 |
| 开发中 | 已进入实现 |
| 待验收 | 实现完成，等待测试 |
| 已完成 | 通过验收并同步文档 |
| 延后 | 已确认不进入当前目标版本 |
| 排除 | 当前项目范围不支持 |

## 10. 功能完成规则

一个功能只有同时满足以下条件才能标记“已完成”：

- [ ] 实际行为符合 PRD。
- [ ] 对应验收标准通过。
- [ ] 必要的单元、集成或端到端测试通过。
- [ ] 不存在未说明的数据丢失或敏感信息泄露风险。
- [ ] 相关文档已经同步。
- [ ] 错误和失败路径得到处理。
- [ ] 代码符合模块依赖规则。

## 11. 待决策事项
