# 验收标准

> 用途说明：定义 MVP 功能达到什么可重复验证的条件才算完成，并建立需求、测试和发布检查之间的对应关系。
>
> 状态：历史内部 MVP 验收基线 / 不再作为当前验收标准
>
> 最后更新日期：2026-07-30

> 现行说明：本文保留早期主密码和锁定方案的验收记录。当前验收以 `docs/09-testing`、ADR-014 和 M4 执行计划为准；本文中的主密码、锁定和解锁用例均已废止。

## 1. 验收规则

- 本文件以内部 MVP 的 P0 需求为主要范围。
- 每条标准必须可以通过测试、检查或明确演示判断为通过或失败。
- “界面看起来正常”不能代替数据持久化、锁定和错误处理验证。
- 所有测试只使用虚构账号、密码、Token 和网址。
- 测试日志、截图和缺陷报告不得包含真实敏感信息。
- P0 标准全部通过后，MVP 才可以进入完成评审。
- MVP 通过不代表可以公开发布或存储真实秘密。

## 2. 测试基线

正式验收前记录：

| 项目 | 记录内容 |
| --- | --- |
| 应用版本或提交 | 待测试时填写 |
| 数据格式版本 | 待实现后填写 |
| Windows 版本 | 待确定 |
| 安装或运行方式 | 开发构建 / 安装包 |
| 测试保险库位置 | 使用专用临时测试目录 |
| 测试数据 | 仅使用虚构数据 |
| 测试结果保存位置 | 待测试策略确定 |

每轮验收应从一个干净测试环境开始，并保留失败步骤和实际结果。

## 3. 端到端核心场景

### E2E-001 完整核心闭环

前置条件：设备上不存在当前测试保险库。

步骤与预期结果：

1. 启动应用，进入首次使用界面。
2. 创建主密码不一致时，应用拒绝继续并给出清晰提示。
3. 使用一致的虚构主密码创建保险库，进入空状态主页。
4. 新建分类“开发”。
5. 在分类下新建网站“示例代码平台”，网址使用受控测试网址。
6. 在网站下新建“私人账号”和“工作账号”两个账号。
7. 两个账号分别填写不同用户名和虚构密码。
8. 为工作账号添加敏感自定义字段“测试令牌”。
9. 保存后，两个账号均可查看且互不覆盖。
10. 关闭并重新启动应用。
11. 输入错误主密码时不能解锁。
12. 输入正确主密码后，分类、网站、两个账号和字段均保持一致。
13. 通过搜索找到网站或账号并进入详情。
14. 分别复制用户名、密码和自定义字段，反馈不显示实际值。
15. 打开有效测试网址时调用系统默认浏览器。
16. 手动锁定后返回解锁界面。
17. 未重新解锁前，不能继续查看或复制保险库内容。

通过条件：以上步骤全部符合预期，且过程中没有无提示数据丢失、敏感日志或应用崩溃。

## 4. 保险库验收

### AC-VAULT-001 首次创建

- [ ] 无保险库时显示创建入口，而不是空白页或不可理解错误。
- [ ] 创建界面说明主密码的重要性和恢复限制。
- [ ] 主密码和确认值为空时不能提交。
- [ ] 两次输入不一致时不能创建保险库。
- [ ] 创建成功后只有一个可识别的有效保险库。
- [ ] 创建失败后再次启动不会把不完整文件当成有效保险库。

### AC-VAULT-002 解锁

- [ ] 正确主密码可以解锁。
- [ ] 错误主密码不能进入保险库主界面。
- [ ] 错误提示不显示主密码、密钥、密文或详细加密参数。
- [ ] 解锁失败后，已输入的密码不会被写入普通日志。
- [ ] 取消或关闭解锁流程不会解密保险库内容。

### AC-VAULT-003 持久化

- [ ] 新增、编辑和删除成功后，正常重启可以看到一致结果。
- [ ] 对象关系、字段顺序和敏感属性在重启后保持一致。
- [ ] 写入失败时应用不得提示“保存成功”。
- [ ] 正式保险库文件中不能直接检索到测试明文密码和测试令牌。
- [ ] 应用不生成包含上述秘密的普通日志或临时文本文件。

仅“在文件中搜索不到明文”不能单独证明加密安全；最终安全验收以加密设计和专项测试为准。

### AC-VAULT-004 手动锁定

- [ ] 主要界面存在可发现的锁定入口。
- [ ] 触发后立即返回解锁界面。
- [ ] 已打开的账号详情不再可见。
- [ ] 锁定前页面上的复制操作不能继续使用。
- [ ] 返回、快捷键或旧界面状态不能绕过解锁。
- [ ] 再次输入正确主密码后才恢复访问。

### AC-VAULT-005 退出

- [ ] 正常关闭应用不会留下可继续操作的可见敏感窗口。
- [ ] 再次启动必须重新解锁。
- [ ] 已确认保存的数据仍然存在。
- [ ] 未确认的编辑如何处理与界面提示一致。

## 5. 分类验收

### AC-CAT-001 新建

- [ ] 输入有效名称可以新建分类。
- [ ] 空名称或仅空白名称不能保存。
- [ ] 首尾无意义空白按统一规则处理。
- [ ] 创建后分类立即出现在正确位置。
- [ ] 重启后分类仍然存在。

### AC-CAT-002 查看与重命名

- [ ] 选择分类可以查看其网站。
- [ ] 重命名后，其下网站和账号关系不变。
- [ ] 取消重命名不会保存更改。
- [ ] 同名情况按数据模型定义的规则处理。

### AC-CAT-003 删除

- [ ] 删除空分类前有明确确认。
- [ ] 取消确认不会删除分类。
- [ ] 删除非空分类时显示受影响的网站数量或可识别内容。
- [ ] 用户未明确选择处理方式前，不删除其网站和账号。
- [ ] 删除完成后的结果在重启后保持一致。

## 6. 网站验收

### AC-SITE-001 新建

- [ ] 可以在选定分类中创建网站。
- [ ] 网站名称为空时不能保存。
- [ ] 网站可以保存有效主网址。
- [ ] 网址留空时允许保存，但打开按钮不可用或给出清晰提示。
- [ ] 新网站不会出现在错误分类中。
- [ ] 重启后网站及所属分类保持一致。

### AC-SITE-002 查看与编辑

- [ ] 网站详情显示名称、网址和账号列表。
- [ ] 修改网站名称不会改变其账号数据。
- [ ] 修改网站网址后，所有账号继续属于该网站。
- [ ] 取消编辑不会写入更改。
- [ ] 保存失败时用户可以知道未成功保存。

### AC-SITE-003 多账号展示

- [ ] 一个网站可以显示至少两个账号。
- [ ] 每个账号通过账号名称或其他非敏感信息区分。
- [ ] 切换账号不会把一个账号的字段显示到另一个账号。
- [ ] 删除其中一个账号不会删除网站或另一个账号。

### AC-SITE-004 删除

- [ ] 删除前显示将受影响的账号数量。
- [ ] 取消后网站及账号保持不变。
- [ ] 用户明确确认后才执行删除。
- [ ] 删除策略和是否可恢复与数据生命周期文档一致。

### AC-SITE-005 打开网址

- [ ] 有效且允许的测试网址可以交给系统默认浏览器打开。
- [ ] 网址为空时不调用系统浏览器。
- [ ] 无效网址给出清晰提示。
- [ ] 不受支持或具有风险的协议不会被静默打开。
- [ ] 打开失败时应用给出不泄露敏感信息的错误反馈。

## 7. 账号验收

### AC-ACC-001 新建多个账号

- [ ] 可以在同一网站下连续创建至少两个账号。
- [ ] 添加第二个账号不会覆盖第一个账号。
- [ ] 账号名称为空时按最终业务规则阻止保存或生成明确默认名称。
- [ ] 两个账号可以保存不同的用户名和密码。
- [ ] 重启后两个账号仍然存在并保持独立。

### AC-ACC-002 查看和编辑

- [ ] 账号列表默认不显示明文密码。
- [ ] 选择账号后显示正确的非敏感字段和被遮挡的敏感字段。
- [ ] 编辑一个账号不会修改同网站其他账号。
- [ ] 取消编辑不保存更改。
- [ ] 保存成功后重新进入详情可以看到更新结果。

### AC-ACC-003 删除

- [ ] 删除前显示可识别的账号名称。
- [ ] 取消确认不删除账号。
- [ ] 删除一个账号不影响其他账号。
- [ ] 网站没有账号时显示合理空状态。
- [ ] 删除结果在重启后保持一致。

## 8. 字段验收

### AC-FIELD-001 基础字段

- [ ] 账号可以保存用户名、密码和备注。
- [ ] 密码默认遮挡。
- [ ] 备注不会出现在普通日志和错误信息中。
- [ ] 字段值保存并重启后保持一致。

### AC-FIELD-002 自定义字段

- [ ] 可以创建至少三个自定义字段。
- [ ] 字段名称为空时不能保存。
- [ ] 每个字段可以保存独立值。
- [ ] 可以把字段标记为敏感或非敏感。
- [ ] 敏感属性在重启后保持一致。
- [ ] 重名字段按最终业务规则得到一致处理。

### AC-FIELD-003 编辑、排序和删除

- [ ] 可以编辑字段名称、值和敏感属性。
- [ ] 可以改变字段顺序。
- [ ] 重新进入账号以及重启后顺序保持一致。
- [ ] 删除一个字段不影响其他字段。
- [ ] 取消编辑或删除不改变已保存数据。

### AC-FIELD-004 显示与隐藏

- [ ] 敏感字段首次进入详情时被遮挡。
- [ ] 用户主动操作后可以临时显示。
- [ ] 用户可以再次隐藏。
- [ ] 切换到其他账号再返回时，不应默认保持长期显示。
- [ ] 锁定后重新解锁，敏感字段恢复为隐藏状态。

## 9. 搜索验收

### AC-SEARCH-001 基础匹配

- [ ] 输入网站名称的一部分可以找到网站。
- [ ] 输入账号名称的一部分可以找到账号。
- [ ] 输入用户名的一部分可以找到账号。
- [ ] 匹配规则对大小写和首尾空白的处理保持一致。
- [ ] 无结果时显示明确空状态。

### AC-SEARCH-002 结果上下文

- [ ] 网站结果显示所属分类。
- [ ] 账号结果显示所属网站。
- [ ] 同名对象可以通过上下文区分。
- [ ] 选择结果可以进入正确详情。

### AC-SEARCH-003 敏感数据边界

- [ ] 搜索结果不显示密码、Token 或其他敏感字段值。
- [ ] MVP 不生成包含秘密字段明文的持久化搜索索引。
- [ ] 锁定状态下不能搜索保险库内容。
- [ ] 搜索输入和结果不会被普通日志完整记录。

## 10. 复制验收

### AC-CLIP-001 复制字段

- [ ] 用户名复制后可在受控测试输入框粘贴为预期值。
- [ ] 密码复制后可在受控测试输入框粘贴为预期值。
- [ ] 网址复制后可粘贴为预期值。
- [ ] 自定义字段复制后可粘贴为预期值。
- [ ] 复制一个字段不会错误复制另一个账号的值。

### AC-CLIP-002 反馈和保护

- [ ] 复制成功后显示短暂反馈。
- [ ] 反馈只说明字段类型或“复制成功”，不显示实际值。
- [ ] 复制失败时给出明确反馈。
- [ ] 锁定状态下不存在可用的敏感字段复制入口。
- [x] 复制内容到期时仅在仍匹配本次写入内容的条件下清理。

自动清除限制与测试已记录在剪贴板安全文档和 M2.5 验收记录中。

## 11. 界面和反馈验收

### AC-UI-001 空状态

- [ ] 新保险库说明如何创建第一条数据。
- [ ] 空分类说明如何添加网站。
- [ ] 无账号网站说明如何添加账号。
- [ ] 无搜索结果不会显示错误或空白页面。

### AC-UI-002 操作反馈

- [ ] 保存成功、复制成功和删除成功有反馈。
- [ ] 保存失败、打开网址失败和删除失败有错误反馈。
- [ ] 错误反馈提供可执行的下一步或允许用户安全返回。
- [ ] 任一反馈都不包含主密码、密码、Token 或密钥。

### AC-UI-003 模块边界

- [ ] 分类、网站、账号、搜索和保险库锁定各有明确职责。
- [ ] 界面关闭或切换不会绕过领域校验和安全校验。
- [ ] 高频查找和复制流程不需要经过无关设置页面。
- [ ] 新模块可以通过定义的接口接入，不要求直接修改所有现有页面。

最终架构验收以模块架构和依赖规则文档为准。

## 12. 数据一致性与异常验收

### AC-DATA-001 关系一致性

- [ ] 账号始终属于存在的网站。
- [ ] 网站始终属于有效分类，或按明确的未分类规则存在。
- [ ] 修改显示名称不会改变内部关联。
- [ ] 删除行为不会产生界面可见的孤立账号。

### AC-DATA-002 保存失败

- [ ] 模拟写入失败时不提示保存成功。
- [ ] 已有有效数据不会被空文件或半写入结果无提示覆盖。
- [ ] 用户能够安全取消或重试。
- [ ] 错误日志不包含敏感字段值。

### AC-DATA-003 异常关闭

- [ ] 在受控条件下模拟异常关闭后，最后一次已确认成功的数据仍可读取，或应用明确进入可恢复错误状态。
- [ ] 应用不会把损坏数据静默当作空保险库。
- [ ] 数据损坏提示与错误主密码提示的内部诊断可区分，用户提示遵循安全设计。

## 13. 隐私和安全基线验收

- [ ] 断开网络后可以完成创建、解锁、增删改查、复制和锁定。
- [ ] 应用不要求注册远程账号。
- [ ] 默认不存在账号数据上传行为。
- [ ] 主密码不出现在配置、普通日志或界面调试信息中。
- [ ] 虚构密码和虚构 Token 不出现在普通日志中。
- [ ] 正式构建不包含固定默认主密码、固定加密密钥或解锁后门。
- [ ] 测试数据指南明确禁止真实秘密。
- [ ] 未完成公开发布门槛前，应用和文档明确标记为内部测试版本。

上述标准只是安全基线，不代替威胁模型、密码学评审和安全专项测试。

## 14. MVP 验收结果

| 类别 | 必须通过 | 阻断条件 |
| --- | --- | --- |
| 核心端到端流程 | E2E-001 | 任一步骤无法完成或数据错误 |
| 保险库 | 所有 P0 条目 | 错误密码可解锁、锁定可绕过 |
| 数据持久化 | 所有 P0 条目 | 明文正式存储、无提示数据丢失 |
| 分类、网站、账号 | 所有 P0 条目 | 关系错乱或删除影响错误 |
| 自定义字段 | 所有 P0 条目 | 字段覆盖、敏感属性丢失 |
| 搜索 | 所有 P0 条目 | 结果泄露秘密或定位错误 |
| 复制与网址 | 所有 P0 条目 | 复制错误账号值或危险协议被静默打开 |
| 隐私基线 | 全部 | 主密码或秘密进入日志、默认上传数据 |

存在以下任一情况时，MVP 不得通过：

- 错误主密码能够进入保险库。
- 锁定后仍能通过正常界面读取秘密。
- 保存成功提示与实际写入结果不一致。
- 删除一个对象会无提示删除无关数据。
- 正式保险库以可直接读取的明文保存秘密。
- 普通日志包含主密码、密码、Token 或密钥。
- 应用把损坏的保险库静默替换为空保险库。
