# 产品需求文档（PRD）

> 用途说明：把项目愿景和范围转换为可设计、可开发、可测试的产品需求，并作为 MVP 实现与验收的主要依据。
>
> 状态：历史内部 MVP PRD / 当前增量由 ADR-014 与 M5 执行计划管理
>
> 最后更新日期：2026-07-30

> 现行说明：本文保留早期主密码和锁定产品方案，便于追溯需求变化。当前产品启动时通过 Windows DPAPI 自动打开 SQLCipher 保险库，不提供主密码、锁定、解锁或自动锁定；相关旧章节不再构成实现或验收要求。

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 当前工作名称 | Web 账号密码管理工具 |
| 产品形态 | 完全本地运行的桌面应用 |
| 首要平台 | Windows，最低版本待确定 |
| 当前阶段 | 产品需求设计 |
| 当前目标版本 | 内部 MVP |
| 主要用户 | 需要在本地管理网站账号的个人用户 |

本 PRD 主要描述内部 MVP。公开试用版本所需的自动锁定、备份恢复、安全验证和发布要求会单独标记。

## 2. 产品背景

用户通常拥有多个网站账号，同一个网站也可能存在私人、工作和测试账号。账号信息如果散落在记忆、便签、聊天记录和文本文件中，会难以查找、容易遗忘，也缺少统一的保护和备份方式。

本产品提供一个本地保险库，以“分类 → 网站 → 多个账号 → 多个字段”为主要组织方式，让用户可以快速保存、查找、复制和使用账号信息。

## 3. 产品目标

### 3.1 MVP 目标

- 验证用户能否清晰管理同一网站下的多个账号。
- 验证基础字段加自定义字段能否覆盖不同网站的信息结构。
- 建立从创建保险库、保存账号、关闭应用到重新解锁读取的完整闭环。
- 验证分类、搜索、复制和打开网址是否足以支持日常查找和使用。
- 建立可以继续扩展而不把业务逻辑堆积在单一界面的模块边界。

### 3.2 首个公开版本目标

- 在 MVP 之上补齐自动锁定、剪贴板保护、备份恢复和数据迁移。
- 完成威胁模型、加密设计、安全测试和恢复测试。
- 提供可理解的安装、使用、安全和数据恢复说明。
- 明确开源许可证和安全漏洞披露流程。

### 3.3 非目标

当前不以实现以下能力为目标：

- 云同步和远程账号体系。
- 团队共享、企业权限和在线后台。
- 浏览器扩展及自动填充。
- Android 或 iOS 应用。
- 动态插件市场。
- 硬件安全密钥、生物识别和远程擦除。

## 4. 目标用户

### 4.1 主要用户

希望在自己的 Windows 设备上保存网站账号，并且不希望核心数据依赖云端服务的个人用户。

### 4.2 典型特征

- 同一个网站可能有多个账号。
- 希望按用途或类别整理网站。
- 除用户名和密码外，还可能需要保存邮箱、Token、恢复码等字段。
- 不具备开发背景，需要界面和错误提示容易理解。
- 希望知道数据存在哪里，并能自行备份和迁移。

## 5. 核心数据结构

MVP 使用以下逻辑层级：

```text
保险库
└─ 分类
   └─ 网站
      └─ 一个或多个账号
         └─ 基础字段与自定义字段
```

业务规则：

- MVP 只支持一个本地保险库。
- 一个网站在 MVP 中归属于一个分类。
- 一个网站可以拥有零个或多个账号。
- 一个账号只属于一个网站。
- 一个账号可以拥有零个或多个自定义字段。
- 用户名、密码、邮箱和备注属于候选基础字段，最终最小集合由数据模型确认。
- 标签和收藏不改变上述主要归属关系。

## 6. 核心使用流程

### 6.1 首次使用

1. 用户启动应用。
2. 应用说明本地数据、主密码和无法绕过主密码恢复数据的风险。
3. 用户创建主密码并再次确认。
4. 应用创建本地保险库。
5. 用户进入空状态主页，并可创建第一个分类或网站。

### 6.2 日常解锁

1. 用户启动应用。
2. 应用显示解锁界面。
3. 用户输入主密码。
4. 验证成功后进入保险库；验证失败时保留在解锁界面并给出不泄露内部细节的提示。

### 6.3 保存账号

1. 用户选择或创建分类。
2. 用户创建网站并填写名称和网址。
3. 用户在网站下添加账号。
4. 用户填写账号名称、基础字段和需要的自定义字段。
5. 用户保存后可以在网站详情中看到该账号。

### 6.4 查找并使用账号

1. 用户通过分类或全局搜索找到网站。
2. 用户选择网站和具体账号。
3. 用户复制用户名、密码或其他字段，或打开网站。
4. 应用只提示“已复制”，不在反馈中显示敏感值。

### 6.5 锁定

1. 用户主动点击锁定。
2. 应用结束当前解锁状态并返回解锁界面。
3. 未重新输入正确主密码前，界面和正常应用接口不得显示保险库内容。

## 7. 优先级定义

| 优先级 | 含义 |
| --- | --- |
| P0 | MVP 必须实现；缺失时不能形成核心闭环 |
| P1 | 首个公开版本必须实现；内部 MVP 可以暂缓 |
| P2 | 有价值但可延后，由版本评审决定 |
| P3 | 长期候选，不进入当前计划 |

## 8. 功能需求

### 8.1 保险库

#### VAULT-001 创建本地保险库（P0）

- 首次启动时，用户可以创建一个本地保险库。
- 创建前应说明主密码的重要性和恢复限制。
- MVP 不要求创建多个保险库。
- 创建失败时不得留下被应用误判为有效的半成品保险库。

#### VAULT-002 设置主密码（P0）

- 用户必须输入并确认主密码。
- 两次输入不一致时不能继续。
- 应提供基础的输入校验和清晰提示。
- 主密码规则和强度提示由安全设计确定，不能仅依赖任意固定最短长度。

#### VAULT-003 解锁保险库（P0）

- 用户输入正确主密码后可以读取保险库。
- 错误主密码不能解锁。
- 错误提示不得泄露加密实现、密钥或敏感数据。
- 是否限制连续失败次数由安全设计决定。

#### VAULT-004 手动锁定（P0）

- 用户可以从主要界面触发锁定。
- 锁定后立即回到解锁界面。
- 锁定后不得继续通过旧页面状态查看或复制敏感字段。

#### VAULT-005 自动锁定（P1）

- 首个公开版本应支持基于空闲时间的自动锁定。
- 是否响应系统休眠、系统锁屏和应用最小化由安全与平台设计确定。
- 默认时长必须兼顾安全和可用性，并允许用户调整。

#### VAULT-006 持久化（P0）

- 保存的数据在正常关闭和重新启动后仍可读取。
- 写入失败必须明确提示，不得显示“已保存”。
- 不允许以明文文件作为保险库的正式持久化形式。

### 8.2 分类

#### CAT-001 新建分类（P0）

- 用户可以输入分类名称并创建分类。
- 分类名称去除无意义的首尾空白。
- 空名称不能保存。

#### CAT-002 查看与重命名分类（P0）

- 用户可以查看分类列表及其包含的网站。
- 用户可以重命名已有分类。
- 同名策略由数据模型决定，并在界面中保持一致。

#### CAT-003 删除分类（P0）

- 删除空分类前需要明确确认。
- 删除非空分类时，必须让用户明确选择取消、移动内容或连同内容删除。
- 不得在无提示情况下级联删除网站和账号。

#### CAT-004 分类排序（P2）

- 用户可以按预设规则或手动方式调整分类顺序。
- MVP 可以先采用固定排序。

### 8.3 网站

#### SITE-001 新建网站（P0）

- 用户可以填写网站名称和主网址。
- 网站必须归属于一个分类。
- 网站名称不能为空。
- 网址允许暂时留空，但打开网址功能在无有效网址时不可用。

#### SITE-002 查看和编辑网站（P0）

- 用户可以查看网站名称、网址和账号列表。
- 用户可以编辑网站信息。
- 修改网站网址后，其下账号无需逐条修改。

#### SITE-003 删除网站（P0）

- 删除网站前必须说明将影响的账号数量。
- 用户确认前不得删除网站及其账号。
- 删除后的恢复能力由数据生命周期设计决定。

#### SITE-004 打开网址（P0）

- 用户可以使用系统默认浏览器打开有效网址。
- 应对网址格式和允许的协议进行验证。
- 无网址或网址无效时不得静默调用系统。

#### SITE-005 网站图标（P2）

- 允许为网站显示图标。
- MVP 可以只使用本地默认图标。
- 任何联网下载图标的功能必须独立说明联网行为。

### 8.4 账号

#### ACC-001 添加多个账号（P0）

- 用户可以在同一网站下添加多个账号。
- 每个账号可以设置用于区分用途的账号名称。
- 添加新账号不得覆盖已有账号。

#### ACC-002 查看账号（P0）

- 网站详情能够清楚展示其账号列表。
- 敏感字段默认隐藏。
- 用户可以选择具体账号查看详情。

#### ACC-003 编辑账号（P0）

- 用户可以修改账号名称、基础字段和自定义字段。
- 取消编辑时不应保存未确认的修改。
- 保存失败时保留可恢复的编辑状态或明确告知用户。

#### ACC-004 删除账号（P0）

- 删除前必须确认并显示可识别的账号名称。
- 删除一个账号不得影响同网站下其他账号。
- 恢复能力由数据生命周期设计决定。

#### ACC-005 收藏账号或网站（P1）

- 用户可以收藏常用对象并快速访问。
- 收藏不改变分类和归属关系。
- 最终收藏网站还是账号，需在界面与数据模型设计中确定。

### 8.5 基础字段与自定义字段

#### FIELD-001 基础字段（P0）

- 账号至少应能表达账号名称、用户名、密码和备注。
- 邮箱可以作为基础字段或预设自定义字段，待数据模型确定。
- 敏感属性不得只由界面视觉状态决定。

#### FIELD-002 新建自定义字段（P0）

- 用户可以设置字段名称和值。
- 用户可以设置字段是否敏感。
- 字段名称不能为空。
- 同一账号内字段重名策略必须明确。

#### FIELD-003 编辑、排序和删除字段（P0）

- 用户可以编辑字段名称、值和敏感属性。
- 用户可以调整字段显示顺序。
- 删除字段前需避免误操作；具体确认规则由交互设计决定。

#### FIELD-004 显示与隐藏敏感字段（P0）

- 敏感字段默认隐藏。
- 用户可以临时显示单个敏感字段。
- 切换账号、锁定或离开敏感详情后，不应无期限保持显示状态。

#### FIELD-005 字段类型（P2）

- 长期可以支持文本、密码、邮箱、网址、日期和多行文本等类型。
- MVP 可先使用文本值加敏感属性，但数据设计需保留类型演进能力。

#### FIELD-006 字段模板（P3）

- 长期允许使用模板快速生成字段集合。
- 模板不得成为读取既有数据的必要依赖。

### 8.6 标签和组织

#### TAG-001 标签（P1）

- 用户可以创建、编辑和删除标签。
- 对象可以拥有多个标签。
- 删除标签不得删除被标记对象。

#### ORG-001 收藏入口（P1）

- 用户可以从固定入口查看收藏对象。
- 空状态应说明如何添加收藏。

#### ORG-002 动态集合（P3）

- 长期可以根据条件形成动态集合。
- 不进入 MVP 或首个公开版本的必选范围。

### 8.7 搜索

#### SEARCH-001 全局搜索（P0）

- 用户可以从主要界面进入搜索。
- MVP 至少匹配网站名称、账号名称和用户名等非秘密标识信息。
- 搜索结果应显示足够的上下文以区分同名对象。
- 用户可以从结果直接进入网站或账号详情。

#### SEARCH-002 敏感字段搜索（待决策）

- 密码、Token 和其他敏感字段默认不应建立可直接读取的明文索引。
- 是否允许临时内存匹配需要单独进行安全和性能评审。

#### SEARCH-003 筛选和排序（P1）

- 首个公开版本可以支持按分类、标签或收藏筛选。
- 具体筛选项由信息架构和用户测试确定。

### 8.8 剪贴板

#### CLIP-001 复制字段（P0）

- 用户可以复制用户名、密码、网址及允许复制的自定义字段。
- 复制成功后显示短暂反馈。
- 反馈不得包含被复制的实际值。

#### CLIP-002 自动清除（P1）

- 首个公开版本应允许在设定时间后尝试清除敏感剪贴板内容。
- 清除前应确认剪贴板仍包含应用写入的内容，避免覆盖用户后来复制的其他内容。
- 必须说明不同操作系统和剪贴板管理器可能保留历史记录。

#### CLIP-003 复制网址（P0）

- 用户可以复制网站网址。
- 复制网址和打开网址是两个独立操作。

### 8.9 界面与反馈

#### UI-001 模块化界面（P0）

- 分类、网站、账号、搜索和设置具有清晰界面边界。
- 高频任务不因模块化而被迫经过过多页面。
- 页面不直接承担唯一的数据加密或业务校验逻辑。

#### UI-002 空状态（P0）

- 新保险库、空分类、无账号和无搜索结果均有可理解的提示。
- 空状态提供适当的下一步操作。

#### UI-003 操作反馈（P0）

- 保存、复制、删除失败和打开网址失败均有明确反馈。
- 成功提示简短，错误提示可指导用户下一步。
- 提示中不得泄露主密码、密码、令牌或解密数据。

#### UI-004 键盘与焦点（P1）

- 首个公开版本应支持合理的键盘导航和清晰焦点状态。
- 密码输入、搜索和主要按钮的焦点顺序应可预测。

### 8.10 设置

#### SETTINGS-001 基础设置（P1）

- 首个公开版本应提供自动锁定、剪贴板清除和基础外观设置。
- 安全设置应解释影响，不使用含糊的“更安全”开关。

#### SETTINGS-002 本地配置（P1）

- 非敏感配置可以单独持久化。
- 配置中不得保存主密码、明文加密密钥或可直接恢复秘密的材料。

### 8.11 备份、恢复和迁移

#### BACKUP-001 加密备份（P1）

- 首个公开版本必须允许用户创建受保护的本地备份。
- 备份必须能够经过完整性验证。
- 备份位置和结果应明确告知用户。

#### BACKUP-002 恢复（P1）

- 用户可以从有效备份恢复。
- 恢复前必须说明对当前数据的影响。
- 恢复完成后应验证数据可读取。

#### MIGRATION-001 数据库迁移（P1）

- 数据格式必须具有版本标识。
- 升级失败不得静默破坏原数据。
- 迁移策略应包含备份、验证和失败恢复。

#### EXPORT-001 导出（P2）

- 导出与备份必须明确区分。
- 如果支持明文导出，必须进行显著风险提示和明确确认。

## 9. 业务规则

### 9.1 名称与重复

- 分类、网站、账号和字段均应具有稳定的内部标识，不能只依赖显示名称。
- 是否允许同名分类或同名网站由数据模型决定。
- 同一网站下允许出现用户名相同但账号名称不同的账号。

### 9.2 删除

- 分类、网站、账号和字段的删除影响不同，必须分别定义。
- 级联删除不得无提示发生。
- 软删除、回收站和永久删除将在数据生命周期文档确定。

### 9.3 保存

- 用户确认保存后才提交编辑内容。
- 保存成功提示必须以持久化成功为前提。
- 关键写入应使用事务或等价的原子保证。

### 9.4 敏感属性

- 密码默认属于敏感字段。
- 自定义字段可由用户指定为敏感。
- 备注可能包含敏感数据，不得写入日志或诊断信息。

## 10. 安全与隐私要求

- 核心功能完全离线可用。
- 保险库不得以明文正式持久化。
- 不保存用户主密码。
- 不在日志、崩溃信息、剪贴板反馈或错误提示中记录秘密。
- 安全实现必须基于成熟组件和单独评审的设计。
- 应区分错误密码、数据损坏和不支持的数据版本，但对外提示不能泄露可被利用的内部细节。
- 内部 MVP 未完成安全评审前，只允许使用虚构测试数据，不应用于保存真实密码或令牌。

## 11. 非功能要求摘要

- 应用在无网络环境下完成全部 P0 流程。
- 常用操作应提供及时反馈，具体性能指标在非功能需求文档中定义。
- 结构应支持模块独立测试。
- 数据变更应具备版本和迁移路径。
- 界面应支持常用键盘操作并具备可辨识的焦点状态。
- 应用异常退出不应轻易破坏已成功保存的数据。

## 12. MVP 验收摘要

MVP 至少完成以下端到端场景：

1. 创建保险库并设置主密码。
2. 创建分类和网站。
3. 在同一网站下创建两个账号。
4. 为其中一个账号添加敏感自定义字段。
5. 关闭并重新启动应用。
6. 使用正确主密码解锁并找到上述数据。
7. 通过搜索定位网站或账号。
8. 复制用户名、密码和自定义字段，并看到不泄露内容的反馈。
9. 打开有效网址。
10. 手动锁定后无法继续查看或复制保险库内容。

所有详细条件以验收标准文档为准。

## 13. 风险

| 风险 | 影响 | 当前处理 |
| --- | --- | --- |
| 过早实现大量未来功能 | 延迟核心闭环 | 以 P0 和 MVP 范围限制开发 |
| 自行设计加密方案 | 产生严重安全缺陷 | 安全设计独立评审，使用成熟组件 |
| 模块化演变为复杂插件系统 | 增加开发和维护成本 | MVP 只要求清晰内部模块 |
| 搜索索引泄露敏感字段 | 破坏保密性 | MVP 不对秘密字段建立明文索引 |
| 删除关系不清导致数据丢失 | 用户无法恢复账号 | 删除前明确影响，数据生命周期另行设计 |
| MVP 被误用于真实数据 | 用户承担未验证风险 | 明确标注内部测试用途，只用虚构数据 |
