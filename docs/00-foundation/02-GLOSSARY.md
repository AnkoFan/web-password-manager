# 术语表

> 用途说明：统一产品、文档、界面和代码中使用的核心术语，避免同一概念出现多种含义。
>
> 状态：初稿 / 待评审
>
> 最后更新日期：2026-07-30

## 1. 使用规则

- 文档和界面优先使用本表中的中文名称。
- 代码、数据库和接口中的英文名称将在命名规范中进一步确定。
- 新增核心概念前，应先检查是否可以复用现有术语。
- 同一个词如果存在不同技术含义，必须在上下文中明确限定。
- 本表描述业务含义，不等同于最终数据库表名或类名。

## 2. 核心业务术语

| 中文术语 | 建议英文 | 定义 |
| --- | --- | --- |
| 保险库 | Vault | 保存一组受统一安全策略保护的数据的逻辑容器。第一版只计划支持一个本地保险库。 |
| 分类 | Category | 用于组织网站或服务的主要层级，例如“工作”“开发”“社交”。分类不同于标签。 |
| 网站 | Website | 用户需要登录的具体网站。为了兼容非网页产品，文档中也可称“网站或服务”。 |
| 服务 | Service | 比“网站”更宽泛的对象，例如没有常规登录网页的 API 服务。第一版界面可以统一以“网站”呈现。 |
| 账号 | Account | 属于某个网站或服务的一组身份及登录信息。一个网站可以拥有多个账号。 |
| 账号名称 | Account Name | 用户用于区分同一网站下多个账号的显示名称，例如“私人账号”“工作账号”。它不一定等于用户名。 |
| 字段 | Field | 账号或网站上的一项具名数据，由字段名称、类型、值、排序和敏感属性等组成。 |
| 基础字段 | Built-in Field | 系统默认提供的常用字段，例如用户名、密码、邮箱和备注。 |
| 自定义字段 | Custom Field | 用户根据需要自行添加的字段，例如 API Key、Token、恢复码或区域。 |
| 敏感字段 | Sensitive Field | 需要默认隐藏并受到更严格复制、日志和内存处理规则保护的字段。 |
| 敏感信息 | Secret | 密码、令牌、私钥、恢复码等需要保密的数据的统称。 |
| 网址 | URL | 与网站、登录页或相关操作关联的网络地址。打开前需要基本验证。 |
| 备注 | Note | 用户填写的补充说明。备注可能包含敏感信息，不能默认视为公开数据。 |
| 标签 | Tag | 跨分类标记对象的轻量方式，例如“重要”“付费”“工作”。一个对象可以拥有多个标签。 |
| 收藏 | Favorite | 用户主动标记的常用对象，用于快速访问，不改变原有分类关系。 |
| 集合 | Collection | 根据固定成员或查询条件组织对象的视图。第一版不要求实现通用集合系统。 |
| 模板 | Template | 用于快速创建一组预设字段或默认配置的可复用定义。模板不拥有实际账号数据。 |
| 字段模板 | Field Template | 专门描述字段名称、类型、顺序和默认敏感属性的模板。 |
| 元数据 | Metadata | 由系统维护的辅助信息，例如创建时间、更新时间、最后使用时间和版本。 |

## 3. 通用对象术语

| 中文术语 | 建议英文 | 定义 |
| --- | --- | --- |
| 条目 | Entry | 可以在列表中展示或操作的一条逻辑信息。必须结合上下文说明是网站条目还是账号条目。 |
| 记录 | Record | 一般指持久化层中的一条数据记录。产品界面不优先使用该词。 |
| 资源 | Resource | 对任何可管理对象的抽象统称，适用于通用接口和未来扩展，不作为第一版主要界面词汇。 |
| 附件 | Attachment | 与对象关联的本地文件，例如证书或许可证文件。附件不在第一版范围内。 |
| 工作区 | Workspace | 一组相互隔离的使用上下文，例如个人或公司空间。它不等同于保险库，第一版不实现。 |

## 4. 安全术语

| 中文术语 | 建议英文 | 定义 |
| --- | --- | --- |
| 主密码 | Master Password | 用户用于解锁保险库的密码。具体密钥派生和验证方式由安全设计确定。 |
| 解锁 | Unlock | 在通过验证后，使应用能够在受控时间内访问保险库数据。 |
| 锁定 | Lock | 终止当前解锁状态，并尽可能清理可访问的敏感内存状态。 |
| 自动锁定 | Auto-lock | 在空闲、休眠、系统锁屏或达到其他条件时自动锁定保险库。 |
| 加密密钥 | Encryption Key | 实际用于加密或解密数据的密钥材料，不等同于主密码。 |
| 密钥派生 | Key Derivation | 使用主密码、盐和参数生成或保护密钥材料的过程。 |
| 盐 | Salt | 密钥派生中使用的非秘密随机值，用于降低预计算攻击风险。 |
| 威胁模型 | Threat Model | 对需要保护的资产、潜在攻击者、信任边界、攻击方式和限制的系统分析。 |
| 明文 | Plaintext | 未加密或已经解密、可直接读取的数据。 |
| 密文 | Ciphertext | 经过加密、在缺少正确密钥时不可直接理解的数据。 |
| 安全删除 | Secure Deletion | 尝试降低已删除数据被恢复可能性的处理。受文件系统和存储介质影响，不能作绝对保证。 |

## 5. 数据与存储术语

| 中文术语 | 建议英文 | 定义 |
| --- | --- | --- |
| 数据模型 | Data Model | 描述业务对象、属性、关系和约束的逻辑模型。 |
| 数据库结构 | Database Schema | 数据库中表、列、索引、关系和约束的具体实现。 |
| 数据迁移 | Migration | 将旧版本的数据结构和数据安全转换为新版本的过程。 |
| 备份 | Backup | 为故障恢复而创建的受保护数据副本。 |
| 恢复 | Restore | 从备份重建可用保险库或应用数据的过程。 |
| 导出 | Export | 将数据转换为供其他软件或人工读取的格式。导出不一定等同于备份。 |
| 导入 | Import | 从外部格式读取、验证并写入项目数据的过程。 |
| 数据可携带性 | Data Portability | 用户能够在不依赖原应用的情况下带走和迁移自己数据的能力。 |
| 软删除 | Soft Delete | 先将对象标记为已删除，但在一定条件下仍可恢复。 |
| 永久删除 | Permanent Delete | 从应用的有效数据集中移除对象且不再提供应用内恢复。它不代表物理介质上绝对不可恢复。 |

## 6. 架构术语

| 中文术语 | 建议英文 | 定义 |
| --- | --- | --- |
| 核心 | Core | 提供稳定领域能力和关键规则的部分，不包含具体页面表现。 |
| 模块 | Module | 具有明确职责、接口、依赖、生命周期和测试边界的功能单元。 |
| 插件 | Plugin | 可以在核心之外独立安装、启用或停用的扩展单元。模块不一定是插件。 |
| 服务接口 | Service Interface | 对数据库、加密、搜索、剪贴板和浏览器等能力的稳定调用契约。 |
| 事件 | Event | 描述已经发生的事实，用于降低模块之间的直接耦合。 |
| 界面层 | Presentation Layer | 展示数据、收集输入并反馈状态的层。 |
| 应用层 | Application Layer | 编排具体用户用例和业务流程的层。 |
| 领域层 | Domain Layer | 表达核心业务对象、规则和约束的层。 |
| 数据层 | Data Layer | 负责持久化、查询、事务和迁移的层。 |
| 平台服务 | Platform Service | 对操作系统能力的封装，例如剪贴板和默认浏览器。 |

## 7. 产品与开发术语

| 中文术语 | 建议英文 | 定义 |
| --- | --- | --- |
| MVP | Minimum Viable Product | 能验证核心用户价值的最小可用版本，不等于可以直接公开发布的成熟版本。 |
| 第一版 | Version 1 | 达到项目定义的首个正式发布标准的版本，范围可能大于 MVP。 |
| 验收标准 | Acceptance Criteria | 判断某项需求是否完成的具体、可验证条件。 |
| 非目标 | Non-goal | 当前阶段明确不实现或不承诺的内容。 |
| 架构决策记录 | ADR | 记录重要技术或架构决定的背景、选项、取舍和结果。 |
| 破坏性变更 | Breaking Change | 使既有接口、模块或数据不能继续兼容的变化。 |

## 8. 容易混淆的概念

### 8.1 分类与标签

- 分类提供主要组织结构。
- 标签用于跨分类标记。
- 第一版中网站是否只能属于一个分类，将由数据模型最终确定。

### 8.2 网站与账号

- 网站保存共享信息，例如显示名称和主网址。
- 账号保存特定身份的信息，例如用户名、密码和自定义字段。
- 一个网站可以有多个账号，一个账号只属于一个网站。

### 8.3 备份与导出

- 备份以完整恢复为目标，通常应保持加密保护。
- 导出以迁移或人工读取为目标，可能产生明文敏感数据。
- 两者必须在界面、文件格式和安全提示中明确区分。

### 8.4 模块与插件

- 模块是内部架构边界。
- 插件是可独立安装或启停的扩展机制。
- 第一版要求模块化，但不要求实现动态插件系统。

### 8.5 主密码与加密密钥

- 主密码是用户记忆和输入的凭据。
- 加密密钥是加密系统使用的密钥材料。
- 两者不应在概念或实现中简单视为同一个值。

## 9. 不推荐使用的模糊词

| 不推荐词 | 原因 | 推荐表达 |
| --- | --- | --- |
| 项目（指一条数据） | 容易与整个软件工程混淆 | 条目、网站或账号 |
| 万能密码 | 容易造成错误安全理解 | 主密码 |
| 绝对安全 | 无法合理保证 | 说明具体安全目标与限制 |
| 云备份 | 可能同时指同步、备份和托管 | 明确写本地备份、远程备份或同步 |
| 删除干净 | 无法说明物理介质恢复边界 | 永久删除，并说明限制 |
