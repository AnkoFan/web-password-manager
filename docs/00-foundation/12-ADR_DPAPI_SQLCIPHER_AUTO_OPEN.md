# ADR-014：DPAPI 保护 SQLCipher 密钥并自动打开

> 状态：已接受
>
> 决定日期：2026-08-01

## 决定

Windows 桌面端使用随机 256 位数据库密钥打开 SQLCipher。数据库密钥由 Windows DPAPI 以当前用户范围自动保护，应用启动时自动解开，不要求用户输入主密码。

项目继续不提供锁定、解锁、自动锁定、失焦锁定、锁屏联动或生物识别入口。

## 文件

- `password-manager.dpapi.db`：SQLCipher 加密数据库。
- `password-manager.dpapi-key`：带固定 magic 与长度边界的 DPAPI 密钥数据。
- `dpapi-backups/<id>/`：数据库、DPAPI 密钥文件与 SHA-256 清单。

数据库与密钥必须成对存在；任一缺失、DPAPI 解密失败、SQLCipher 完整性失败或 schema 不兼容时停止写入，不创建空数据库覆盖原文件。

## 兼容策略

- 不迁移、不读取、不覆盖 `password-manager.db` 明文测试库。
- 不迁移旧 `vault.db`、`vault.header.json` 或旧备份。
- 因为全部数据均为虚构测试数据，新格式首次启动创建空的加密数据库。

## 后果与限制

- 静态数据库页面由 SQLCipher 加密，随机密钥不以明文写入磁盘。
- DPAPI 保护绑定 Windows 用户配置文件；复制文件到其他用户或没有原 DPAPI 凭据的设备通常无法恢复。
- 当前用户上下文中的恶意程序、管理员级攻击、应用运行期内存读取、屏幕与剪贴板不由静态加密解决。
- 没有主密码意味着应用启动后会自动显示数据；系统锁屏、睡眠和切换应用不会触发应用锁定。
- 备份必须同时保留数据库和 DPAPI 密钥文件。

## 被取代的决定

本决定取代 ADR-013 的普通明文 SQLite 存储选择，但保留其“不再添加锁定设计”的产品决定。ADR-007、ADR-010、ADR-012 的主密码/KDF/安全头方案仍保持废止。
