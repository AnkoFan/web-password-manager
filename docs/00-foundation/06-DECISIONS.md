## 3. ADR-001 完全本地

决定：

- 不建立服务器、远程账号和云同步。
- 不默认发送遥测、崩溃数据和图标请求。
- 打开网址是用户主动交给默认浏览器的操作。

理由：符合用户数据控制权，并显著缩小第一阶段安全范围。

## 4. ADR-002 单一安装入口

决定：

- Windows 发布一个 NSIS `Setup.exe`。
- 不安装服务、驱动、浏览器扩展和计划任务。
- 程序与保险库数据分离。
- 卸载默认保留保险库。

理由：保持普通用户安装体验简单，同时允许应用内部拥有必要运行文件。

## 5. ADR-003 编译期模块

决定：

- 分类、网站、账号、字段和搜索以清晰模块组织。
- MVP 在组合根中编译期注册。
- 动态插件仅作为长期候选。

理由：满足模块化原则，避免过早引入插件签名、沙箱和兼容复杂度。

## 6. ADR-004 多账号与统一字段

决定：

- 一个网站保存共享名称和网址。
- 一个网站包含多个账号。
- 用户名、密码、邮箱、备注和自定义字段使用统一 `AccountField` 模型。
- 系统角色与可修改显示标签分离。

理由：避免重复网站数据，并支持任意服务字段。

## 7. ADR-005 名称规则

决定：

- 分类名在保险库内唯一。
- 网站名允许重复但提示。
- 账号显示名在网站内唯一。
- 字段标签在账号内唯一。

理由：在防止歧义和允许不同环境同名网站之间取得平衡。

## 8. ADR-006 软删除

决定：

- 分类、网站和账号使用 `deletedAt` 与 `deletionGroupId`。
- 回收站不自动过期，由用户主动清空。
- 字段在账号保存事务中删除，不单独进入回收站。

理由：密码数据误删代价高，本地回收站比立即删除更安全。

## 9. ADR-007 分层密钥

决定：

- 生成随机 256 位 DEK 加密数据库。
- 主密码通过 Argon2id 派生 KEK。
- KEK 使用 AEAD 包装 DEK。
- 修改主密码只重新包装 DEK。

理由：便于安全修改主密码和升级 KDF 参数，不需要重加密全部数据。

## 10. ADR-008 Tauri 技术栈

候选决定：

- Tauri 2 + Rust 后端。
- React 19 + TypeScript + Vite 前端。
- Tailwind CSS 4 + shadcn/ui。

接受条件：

- Windows 原型、锁定边界和离线 NSIS 安装测试通过。

备选：如 Tauri 原型失败，重新评估纯 .NET 或 Electron，不能同时维护双框架。

## 11. ADR-009 SQLite + SQLCipher

候选决定：

- SQLite 负责事务、关系和迁移。
- SQLCipher 负责数据库静态加密。
- 使用随机 DEK 原始密钥打开。

接受条件：

- Rust 绑定、Windows 构建、备份、恢复、篡改检测和安装打包原型通过。

## 12. ADR-010 Argon2id

决定：

- 使用 Argon2id 1.3。
- 每保险库随机盐。
- 参数存入安全头并可升级。
- 初始候选为 64 MiB、3 次迭代，最终值由最低支持设备基准确定。

## 13. ADR-011 AEAD 包装

决定：

- 使用标准 AEAD 包装 DEK并认证关键安全头。

候选：

- AES-256-GCM。
- 如果 Rust 依赖审查更合适，采用 XChaCha20-Poly1305。

禁止自行实现密码算法。
