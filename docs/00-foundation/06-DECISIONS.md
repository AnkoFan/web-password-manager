## 3. ADR-001 完全本地

决定：

- 不建立服务器、远程账号和云同步。
- 不默认发送遥测、崩溃数据和图标请求。
- 打开网址是用户主动交给默认浏览器的操作。

理由：符合用户数据控制权，并显著缩小第一阶段安全范围。

## 4. ADR-002 单一安装入口

决定：

- Windows 发布一个 NSIS `Setup.exe`。
- 不安装服务、驱动、浏览器扩展和计划任务。
- 程序与保险库数据分离。
- 卸载默认保留保险库。

理由：保持普通用户安装体验简单，同时允许应用内部拥有必要运行文件。

## 5. ADR-003 编译期模块

决定：

- 分类、网站、账号、字段和搜索以清晰模块组织。
- MVP 在组合根中编译期注册。
- 动态插件仅作为长期候选。

理由：满足模块化原则，避免过早引入插件签名、沙箱和兼容复杂度。

## 6. ADR-004 多账号与统一字段

决定：

- 一个网站保存共享名称和网址。
- 一个网站包含多个账号。
- 用户名、密码、邮箱、备注和自定义字段使用统一 `AccountField` 模型。
- 系统角色与可修改显示标签分离。

理由：避免重复网站数据，并支持任意服务字段。

## 7. ADR-005 名称规则

决定：

- 分类名在保险库内唯一。
- 网站名允许重复但提示。
- 账号显示名在网站内唯一。
- 字段标签在账号内唯一。

理由：在防止歧义和允许不同环境同名网站之间取得平衡。

## 8. ADR-006 软删除

决定：

- 分类、网站和账号使用 `deletedAt` 与 `deletionGroupId`。
- 回收站不自动过期，由用户主动清空。
- 字段在账号保存事务中删除，不单独进入回收站。

理由：密码数据误删代价高，本地回收站比立即删除更安全。

## 9. ADR-007 分层密钥

状态：已由 ADR-014 取代；以下仅保留历史决定。

决定：

- 生成随机 256 位 DEK 加密数据库。
- 主密码通过 Argon2id 派生 KEK。
- KEK 使用 AEAD 包装 DEK。
- 修改主密码只重新包装 DEK。

理由：便于安全修改主密码和升级 KDF 参数，不需要重加密全部数据。

## 10. ADR-008 Tauri 技术栈

决定：

- Tauri 2 + Rust 后端。
- React 19 + TypeScript + Vite 前端。
- Tailwind CSS 4 + shadcn/ui。

接受证据：Windows 原型、锁定边界、离线 NSIS 安装和 M2.6 远程门禁已经通过。

## 11. ADR-009 SQLite + SQLCipher

决定：

- SQLite 负责事务、关系和迁移。
- SQLCipher 负责数据库静态加密。
- 使用随机 DEK 原始密钥打开。

接受证据：Rust 绑定、Windows 构建、备份、恢复、篡改检测和安装打包原型已经通过。

## 12. ADR-010 Argon2id

状态：已由 ADR-014 取代；当前保险库打开流程不使用用户口令 KDF。

决定：

- 使用 Argon2id 1.3。
- 每保险库随机盐。
- 参数存入安全头并可升级。
- 初始候选为 64 MiB、3 次迭代，最终值由最低支持设备基准确定。

## 13. ADR-011 AEAD 包装

状态：已由 ADR-014 取代；当前数据库密钥由 Windows DPAPI 保护。

决定：

- 使用标准 AEAD 包装 DEK并认证关键安全头。

实现选择：

- XChaCha20-Poly1305。
- 192 位随机 nonce。
- RustCrypto 维护实现。

禁止自行实现密码算法。

## 14.1 ADR-012 安全头格式 v2

状态：已由 ADR-014 取代；以下保留 M3 早期方案的历史记录，不适用于当前文件格式。

决定：

- 新建保险库使用带 magic、vault ID、嵌套 KDF 与密钥包装信息的安全头 v2。
- AAD 使用独立于 JSON 序列化的固定顺序二进制规范编码。
- KDF 参数先通过绝对资源边界，再匹配经过基准和评审的已知配置。
- v1 只有在完整验证并建立持久迁移快照后才能单向迁移到 v2。
- schema 迁移、v2 头暂存、头替换和启动恢复必须遵守可注入失败的提交协议。

完整决定见 [ADR-012](10-ADR_VAULT_HEADER_V2.md)。

## 14.2 ADR-014 DPAPI + SQLCipher 自动打开

决定：

- Windows CSPRNG 生成随机 256 位 SQLCipher 数据库密钥。
- 当前 Windows 用户 DPAPI 保护密钥，启动时自动解开并打开数据库。
- 产品不提供主密码、锁定、解锁或自动锁定。
- 数据库/密钥文件对不完整、DPAPI 不匹配、数据库损坏或 schema 不兼容时安全停止且不覆盖文件。

完整决定见 [ADR-014](12-ADR_DPAPI_SQLCIPHER_AUTO_OPEN.md)。
