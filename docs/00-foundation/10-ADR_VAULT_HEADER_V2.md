# ADR-012：安全头格式 v2 与可恢复迁移

> 状态：已接受
>
> 决策日期：2026-07-31
>
> 适用版本：M3 / `0.2.0-beta.1`

## 1. 背景

安全头 v1 已能使用 Argon2id 派生 KEK，并用 XChaCha20-Poly1305 包装数据库 DEK，但存在以下限制：

- 没有 magic 和稳定的保险库标识。
- KDF 参数必须与编译期常量完全相同，无法表达受控升级。
- AAD 使用带分隔符的字符串拼接，不是独立于 JSON 的规范编码。
- 现有解锁路径在创建迁移前快照之前执行数据库 schema 迁移。
- 头格式、数据库 schema 和备份清单的 `formatVersion` 语义没有集中说明。

M3 必须在不轮换 DEK、不重写全部数据库且不把失败状态误判为空保险库的前提下，支持从 v1 单向迁移到 v2。

## 2. 决策

### 2.1 四个独立版本轴

以下版本互相独立，不允许由一个版本推断另一个版本：

1. 应用 SemVer。
2. 安全头 `formatVersion`。
3. SQLite `user_version` 与 `schema_migrations`。
4. 备份或迁移快照清单 `formatVersion`。

M3 新建保险库使用安全头 v2、数据库 schema v2 和备份清单 v1。

### 2.2 v2 JSON 结构

安全头仍使用 UTF-8 JSON，最大 64 KiB。序列化字段采用 camelCase：

```json
{
  "magic": "WPMVAULT",
  "formatVersion": 2,
  "vaultId": "00000000-0000-4000-8000-000000000000",
  "kdf": {
    "algorithm": "argon2id",
    "version": 19,
    "saltHex": "00000000000000000000000000000000",
    "memoryKiB": 65536,
    "iterations": 3,
    "parallelism": 1,
    "outputLength": 32
  },
  "keyWrap": {
    "algorithm": "xchacha20poly1305",
    "nonceHex": "000000000000000000000000000000000000000000000000",
    "wrappedDekHex": "TEST-FIXTURE-REPLACES-THIS-WITH-VALID-HEX"
  }
}
```

示例只描述结构，不是有效保险库，也不包含真实密钥材料。

约束：

- `magic` 必须精确为 ASCII `WPMVAULT`。
- `formatVersion` 必须为 `2`。
- `vaultId` 必须是小写、带连字符的规范 UUID；其 16 个原始字节必须与数据库唯一 `vault_meta.id` 一致。
- KDF 算法只接受 `argon2id`，版本只接受 `19`（Argon2 1.3）。
- 盐固定 16 字节，KDF 输出固定 32 字节。
- 密钥包装算法只接受 `xchacha20poly1305`，nonce 固定 24 字节，包装结果固定 48 字节。
- JSON 未知字段在 v2 中拒绝，避免调用方误以为已经认证并执行了扩展语义。
- 十六进制只接受小写 ASCII，长度必须在解码前检查。

### 2.3 KDF 配置注册表

解析器先执行绝对资源边界检查，再匹配应用内的已知配置。M3.2 初始注册表只有：

| 配置 | memoryKiB | iterations | parallelism | outputLength |
| --- | ---: | ---: | ---: | ---: |
| `argon2id-19-m65536-t3-p1` | 65536 | 3 | 1 | 32 |

绝对解析边界：

- `memoryKiB`：65536–262144。
- `iterations`：3–10。
- `parallelism`：1–4。
- `outputLength`：只能为 32。

落在绝对边界内但不属于已知配置的参数仍必须在执行 KDF 前拒绝。M3.3 只有在最低支持 Windows 设备完成基准后，才能新增“当前创建配置”或升级目标。不得因内存分配失败静默降低参数。

### 2.4 v2 规范 AAD

AAD 不依赖 JSON 键顺序、空白或序列化库。它按以下顺序拼接：

1. ASCII 域分隔符 `WPM-VH2-AAD`，后跟单个 `0x00`。
2. `formatVersion`：无符号 32 位大端。
3. `magic`：8 个 ASCII 字节。
4. `vaultId`：16 个 UUID 原始字节。
5. KDF 算法 ID：`0x01` 表示 Argon2id。
6. Argon2 版本：无符号 32 位大端，值为 19。
7. KDF 盐：16 个原始字节。
8. `memoryKiB`、`iterations`、`parallelism`、`outputLength`：各为无符号 32 位大端。
9. 包装算法 ID：`0x01` 表示 XChaCha20-Poly1305。
10. 包装 nonce：24 个原始字节。

`wrappedDekHex` 不进入 AAD；包装密文本身已经由 AEAD 标签认证。任何 AAD 字段或 nonce 变化都会使解包失败。

### 2.5 v1 兼容边界

- v1 只接受 M2.6 已发布的精确算法、长度和 KDF 常量。
- v1 解包继续使用原字符串 AAD，不能用 v2 AAD 尝试解包。
- v1 成功解包并验证数据库后必须迁移为 v2；应用不再用 v1 写入新头。
- 未知头版本、未知算法、未知 KDF 配置或高于当前的数据库 schema 均保持文件不变并安全拒绝。
- 只要正式头、数据库或迁移残留任一存在，就不得进入“创建新保险库”路径。

## 3. 迁移协议

迁移操作拥有随机 UUID `operationId`。所有文件位于保险库应用数据目录，不使用系统公共临时目录。

### 3.1 顺序

1. 检查并恢复上次迁移残留；无法唯一确定有效状态时停止并提示恢复。
2. 限制大小并严格解析 v1 头。
3. 解包 DEK，打开 SQLCipher，验证密文完整性、逻辑完整性和保险库标记。
4. 只读取 schema 状态，不执行迁移；高于当前或内部不一致时停止。
5. 创建 `migration-backups/<operationId>.creating/`，复制原头和数据库。
6. 同步两个副本，写入并同步迁移清单；清单记录自身版本、操作 ID、原头版本、原 schema 版本、长度和 SHA-256。
7. 将目录重命名为 `migration-backups/<operationId>/`，再同步父目录。完成前不得修改正式文件。
8. 在 SQLCipher 事务中执行 schema 迁移并验证，提交后同步数据库。
9. 从数据库唯一 `vault_meta.id` 取得 `vaultId`；生成新盐与 nonce，使用当前已知 KDF 配置重新包装同一 DEK。
10. 写入 `vault.header.json.migrating-<operationId>`，同步、重读、重新解包并核对 DEK 和 `vaultId`。
11. 把正式 v1 头重命名为 `vault.header.json.rollback-<operationId>`。
12. 把已验证 v2 暂存头重命名为正式头，同步正式头和父目录。
13. 用正式 v2 头重新打开并完整验证数据库。
14. 验证成功后删除回滚头和暂存残留；保留迁移快照作为用户可见恢复证据，直到用户明确删除。

数据库 schema 事务先于头替换。若进程在二者之间终止，v1 头仍可解包同一 DEK并安全重试头迁移。

### 3.2 启动恢复

- 正式头和数据库均有效时优先使用正式文件；验证完成后才清理同一操作的无效暂存文件。
- 正式头缺失且存在唯一有效回滚头时，先把回滚头恢复为正式头，再重新开始迁移。
- 正式头缺失且只有唯一已验证的 v2 暂存头时，可提交该头，但必须先验证它能解包并匹配数据库 `vaultId`。
- 同时存在多个操作 ID、多个有效候选或头库不匹配时不得自动选择。
- `.creating` 快照不作为恢复源；只有清单、长度和 SHA-256 全部通过的最终迁移快照才可用于人工恢复。
- 清理失败只报告残留，不得把已经验证的正式保险库判为损坏。

## 4. 失败不变量

每个失败点都必须保持：

- 不返回部分业务数据。
- 不记录主密码、KEK、DEK、包装密文或业务秘密。
- 不把现有或残留保险库识别为“尚未创建”。
- 不覆盖最后一个已完整验证的头/数据库组合。
- 不静默降低 KDF 参数或猜测未知算法。
- 错误密码、篡改和资源限制对 UI 使用最小且不泄露内部状态的错误类别。

## 5. 降级策略

安全头 v2 是单向迁移。`0.1.0` 不支持 v2，用户必须使用迁移快照恢复 v1 文件后才能降级。M3 UI 和发布说明必须在首次迁移前说明这一点。M3 不自动执行格式降级。

## 6. 备选方案

- 继续扩展 v1：拒绝，因为无法可靠区分旧字段语义和新认证语义。
- 对 JSON 文本整体做 AAD：拒绝，因为空白、键顺序和序列化器差异会破坏兼容性。
- 迁移时轮换 DEK或重写数据库：拒绝，增加数据损坏窗口且不是格式升级所必需。
- 失败时创建空保险库：拒绝，可能覆盖可恢复状态。
- 用 SHA-256 代替代码签名：拒绝，校验值不能在发布渠道同时受损时证明发布身份。

## 7. 验证要求

- v1 固定虚构夹具能够读取并迁移。
- v2 AAD 固定向量跨序列化顺序保持一致。
- magic、vault ID、KDF、nonce、包装密文、标签和数据库任一篡改均安全拒绝。
- 每个迁移文件操作点均可注入失败并验证原组合或迁移快照可恢复。
- v2 与未来 schema、未知字段、未知 KDF 配置均在写入前拒绝。
- 旧版本打开 v2 后不得覆盖任何文件。
- 迁移日志和错误输出通过测试秘密扫描。
