## 2. UI-only 边界

- 不修改 Rust 命令、领域约束、数据库 schema、DPAPI/SQLCipher 文件对、备份格式或剪贴板安全逻辑。

## 3. 现状审计

### 主工作区

- 1280×720 下账号表最小宽度为 `62rem`，主内容区出现水平滚动，网站信息、账号输入和七个以上图标操作挤在单行。
- 网站与账号的父子关系主要依赖同一表格行表达；账号增加后扫描路径长，主操作和危险操作缺少稳定分组。
- 空状态在大画布中信息密度过低，创建路径只表达当前一步，没有预示“分类 → 网站 → 账号”的完整流程。
- 搜索框独占顶部中央区域，但当前分类标题和主要操作与搜索之间缺少连续的工作区层级。

### 账号详情

- 弹窗同时承载基础字段、敏感操作、帮助说明和自定义字段；内容必须内滚动，首屏层级偏密。
- 用户名与密码并列、邮箱和备注独占整行，图标操作散落在输入框尾部，阅读顺序与操作分组不够稳定。
- 自定义字段位于折叠线以下，用户难以预判字段数量和保存范围。

### 设置与辅助页面

- 设置采用不等高卡片网格，安全说明、可编辑设置和备份操作混在同一视觉层级；主要设置会因页面高度落到首屏以下。
- 回收站、搜索和设置沿用不同密度与容器模型，尚未形成统一页面标题、工具栏、列表和状态组件族。
- 当前颜色与可访问性基础可保留，但排版、间距、边框、圆角和图标按钮需要统一令牌。

## 4. 已选视觉方向

- 定位为安静、可信、低干扰的 Windows 本地工具，不采用营销页、卡片墙或装饰性渐变。
- 使用真白主内容、浅青灰导航面、石墨色正文与克制的深青主色；危险操作只在明确删除路径使用红色。
- 桌面主界面采用“分类导航 / 网站列表 / 账号工作区”三栏结构，避免账号表横向滚动。
- 账号以可扫描列表呈现；选中账号后在主工作区查看或编辑，复制、显示、打开和更多操作按语义分组。
- 设置使用单列分区与清晰摘要，不使用不等高卡片拼贴。
- 动效只用于选择、展开、保存反馈和对话框进入；完整支持 `prefers-reduced-motion`。

## 5. 概念确认门槛

- 主界面必须同时表现分类、多个网站、多个账号、搜索和关键操作。
- 必须提供账号详情编辑状态；设置页沿用同一设计系统。
- 1280×720 不出现主内容水平滚动，900×640 和 450×640 有明确降级布局。
- 所有可见文案来自现有产品语义，不引入未实现功能、假指标或联网承诺。
- 概念确认后，颜色、密度、容器模型、图标风格和信息架构作为实现规格冻结。
