# 第三阶段 M3 执行计划

> 状态：执行中；仅使用虚构测试数据

## 1. 基线核对

M3 最初从 `main` 开始，`m2.6-internal` 作为不可移动回归基线。

| 引用 | 提交 | 说明 |

| 当时的 `origin/main` | `ceaa4cd35cad20f394321cca04cb2cc679e82b5f` | 在 M2.6 上增加文档交接，不含生产代码差异 |

后续 M3 已完成安全、迁移、Windows 生命周期、安装和可用性测试。2026-08-01 产品决定取消全部锁定/解锁和加密设计，并明确选择普通未加密本地存储。旧 M3.2–M3.4 的加密/KDF/锁定成果只作为历史证据，不再是当前产品要求。

## 2. 当前范围

- 保留账号管理、搜索、字段显示/复制、软删除/恢复、网址打开和剪贴板条件清理。
- 活动存储改为 `password-manager.db` 普通 SQLite。
- 备份改为 `plaintext-backups/<backup-id>/password-manager.db` 与 SHA-256 清单。
- 删除创建主密码、锁定、解锁、自动锁定、失焦锁定和 Windows 会话锁定。
- 不迁移、不删除旧 `vault.db`、安全头或旧加密备份。
- 不增加其他锁定设计。

## 3. 增量与完成定义

### M3.R1 普通 SQLite 核心

- 删除 SQLCipher、Argon2、AEAD、Windows 生命周期监听依赖和代码。
- 启动时打开或创建数据库，并验证 schema、应用标记和 `PRAGMA integrity_check`。
- Rust 测试确认文件以 `SQLite format 3` 开头，关闭后可重新打开。

### M3.R2 产品界面与契约

- 删除创建/解锁页面、锁定按钮、锁定事件和自动锁定设置。
- 主界面直接启动；失败时进入可重试恢复状态。
- 设置页明确说明数据库和备份均未加密。
- 浏览器内存原型与 Tauri 契约保持一致。

### M3.R3 备份与恢复

- 在线创建 SQLite 一致性备份。
- 恢复前验证清单、SHA-256、数据库完整性和 schema。
- 损坏备份不得替换当前数据库；成功恢复后重新打开连接。

### M3.R4 回归与 Windows 验收

- `npm run check`、RustSec 和 npm audit 通过。
- 浏览器真实渲染确认没有主密码、锁定或解锁入口，设置页警示可见。
- 当前 Windows 安装、覆盖、卸载、数据保留/清理和恢复重新通过。
- 所有账号、网址、字段、Token 和截图仅使用 `TEST-ONLY` 虚构值。

### M3.R5 候选冻结

- README、路线图、安全模型、存储、质量和发布清单与实现一致。
- 发布说明突出明文风险；不得描述为安全密码保险库。
- 记录候选提交、安装包 SHA-256 和未签名状态。

## 4. 停止条件

- 发现真实凭据或来源不明数据。
- 新数据库或备份被错误描述为加密。
- 旧加密文件被自动迁移、覆盖或删除。
- 任一自动化门禁或关键 Windows 验收失败。

## 5. 决策依据

当前范围由 [ADR-013](11-ADR_PLAINTEXT_STORAGE_NO_LOCK.md) 冻结。历史安全头设计见 ADR-012，但已被取代。
