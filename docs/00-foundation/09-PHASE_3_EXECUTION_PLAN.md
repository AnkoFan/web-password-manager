# 第三阶段 M3 执行计划

> 当前增量：Windows DPAPI + SQLCipher 自动加密
>
> 状态：执行中；仅虚构测试数据

## 基线

`m2.6-internal`（`b594757953f56b5022f39ceb5a61403c540f70c3`）保持不可移动回归基线。M3 从 `main` 开始，经历了旧主密码方案、无锁定明文方案，当前由 ADR-014 冻结为“自动 DPAPI 加密、无锁定界面”。

## 当前范围

- 保留账号管理、搜索、字段操作、软删除/恢复、网址打开和剪贴板清理。
- SQLCipher 使用随机 256 位数据库密钥。
- Windows 当前用户 DPAPI 自动保护密钥；启动时自动打开。
- 备份包含 SQLCipher 数据库、DPAPI 密钥文件和完整性清单。
- 不恢复主密码、锁定/解锁、自动锁定、失焦/锁屏/睡眠监听。
- 不迁移、不读取、不覆盖旧明文或旧加密测试数据。

## 完成定义

### 核心与失败边界

- DPAPI 往返与篡改拒绝测试通过。
- SQLCipher 文件头不是 `SQLite format 3`，密文与逻辑完整性通过。
- 数据库/密钥文件只有一个存在时安全停止且不覆盖。
- DPAPI 用户不匹配、密钥损坏、数据库损坏和 schema 不兼容均停止写入。

### 备份恢复

- `sqlcipher_export` 创建加密一致性副本并保留 schema 版本。
- 两个备份文件的长度、SHA-256、DPAPI、SQLCipher 和 schema 均验证。
- 双文件恢复失败时回滚到原组合。

### UI 与验证

- 启动直接进入主界面，没有锁定/解锁入口。
- 设置页说明 Windows DPAPI 自动加密和跨用户恢复限制。
- 前端、Rust、npm audit、RustSec、敏感面和浏览器渲染门禁通过。
- Windows 安装包首次启动/重启、文件头和备份恢复通过。

## 停止条件

- 使用真实凭据或来源不明数据。
- 旧测试文件被迁移、覆盖或删除。
- UI 重新出现锁定/解锁功能。
- 数据库以普通 SQLite 文件头落盘，或 DPAPI 明文密钥写入文件/日志。
