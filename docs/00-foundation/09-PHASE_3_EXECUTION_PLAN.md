# 第三阶段 M3 执行计划

> 制定日期：2026-07-30
>
> 状态：执行中 / M3.1、M3.2、M3.4 与当前 Windows 可用性已完成；M3.3 最低设备、M3.5 正式迁移安装和发布治理待关闭

## 1. 阶段目标与基线

M3 的目标是把第二阶段内部版本推进到可邀请外部用户试用的公开测试版门槛。第三方或独立安全评审、Windows 人工验收和发布治理全部完成前，应用继续只使用虚构测试数据，不用于保存真实秘密。

| `main` / `origin/main` | `ceaa4cd35cad20f394321cca04cb2cc679e82b5f` | 在 M2.6 基线上增加 1 个 M2 关闭与 M3 交接提交 |

`m2.6-internal` 是 `main` 的祖先；两者之间只包含 `README.md`、`CHANGELOG.md` 和 `docs/` 下的文档变更，没有生产代码、依赖、构建配置或测试代码差异。M3 从 `main` 开始，`m2.6-internal` 保留为不可移动的回归基线。

远端 `main` 最新提交的作者邮箱为 `2233917050@qq.com`，提交正文同时记录了规范 noreply 身份的共同作者。M3 发布治理需要明确唯一公开提交身份，并确保后续提交和合并证据与发布检查清单一致；不为此改写已经接受的 M2 历史。

## 2. 版本与公开测试边界

- M3 首个公开测试候选版本提议为 `0.2.0-beta.1`。
- 当前清单中的 `0.1.0` 在进入发布候选增量前保持不变，避免设计阶段产物被误认为可发布版本。
- 不预先承诺发布日期。只有全部退出条件具备可复核证据后才创建发布候选。
- 公开测试仍是 Windows 单机、本地保险库、单用户边界。
- 不纳入云同步、遥测、远程脚本、浏览器扩展、团队共享、动态插件、移动端或明文导出。
- 任何示例、自动化夹具、截图、备份、缓存和崩溃测试只使用明确标记的虚构身份、网址、密码与 Token。

## 3. M3 退出条件

以下条件全部满足后，才允许创建 `0.2.0-beta.1` 发布候选：

1. 安全头格式 v2、KDF 参数升级和迁移前备份/失败恢复完成设计评审、实现和自动化回归。
2. 威胁模型覆盖公开分发、安装包替换、升级降级、迁移中断、WebView2 缓存、临时文件和崩溃转储。
3. 现有前端、Windows Rust/SQLCipher、RustSec、npm audit 和敏感面扫描门禁全部通过，且没有未说明的忽略项。
4. 使用虚构保险库完成 Windows 锁屏、休眠/唤醒、切换用户、切换应用、异常退出和剪贴板历史人工验收。
5. 完成全新安装、覆盖升级、卸载、数据保留/清理和备份恢复测试。
6. 无障碍、键盘操作、错误状态和发布说明达到验收标准。
7. 开源许可证正文、安装包 SHA-256、代码签名决定和统一发布身份具备记录。
8. 完成第三方或独立安全评审；所有阻断项关闭或有明确的不发布决定。
9. 仓库公开后为 `main` 启用必需 CI 检查和分支保护。

在以上条件全部通过前，不移除“仅使用虚构测试数据”的限制，也不宣称版本适合保存真实秘密。

## 4. 版本轴与兼容矩阵

安全头格式、数据库 schema、备份清单和应用版本是四个独立版本轴。实现不得用其中一个版本推断其他版本。

当前基线：

- 应用版本：`0.1.0`。
- 安全头格式：v1。
- 数据库 schema：v2。
- 备份清单格式：v1。
- KDF：Argon2id 1.3，64 MiB、3 次迭代、并行度 1。

目标兼容行为：

| 输入组合 | M3 读取 | M3 写入 | 预期处理 |
| --- | --- | --- | --- |
| 头 v1 + schema v0/v1 + 已支持 KDF | 是 | 迁移后 | 先验证并创建迁移前备份，再按顺序迁移 schema 和头格式 |
| 头 v1 + schema v2 + 已支持 KDF | 是 | 迁移后 | 验证备份后把头升级为 v2；不重加密全部数据库 |
| 头 v2 + schema v2 + 当前 KDF | 是 | 是 | M3 正常路径 |
| 头 v1/v2 + 未知或越界 KDF | 否 | 否 | 在执行 KDF 前安全拒绝，不静默降级 |
| 未知头版本 | 否 | 否 | 保持文件不变并提示需要兼容版本 |
| 已支持头 + 高于当前的 schema | 否 | 否 | 只读也不尝试，保持文件不变 |
| 头与数据库错配、任一文件截断或篡改 | 否 | 否 | 统一失败，不返回部分业务数据 |
| 备份清单 v1 + 支持的头/schema | 是 | 恢复后按正常迁移 | 先验证摘要和可解锁性，再替换当前保险库 |
| 未知备份清单版本 | 否 | 否 | 替换当前保险库前安全拒绝 |

表中的“迁移后”是目标策略，不表示现有 `0.1.0` 已具备该能力。实际实现前必须由独立 ADR 冻结 v2 字段、规范编码、关联数据、允许的 KDF 范围和提交协议。

## 5. 增量顺序

### M3.1 范围、格式与迁移设计门禁

目标：冻结版本规则、格式 v2 决策、兼容矩阵、失败恢复协议和测试清单；不修改保险库运行时代码。

交付物：

- 完善版本规则，记录 `0.2.0-beta.1` 的含义和发布日期条件。
- 新增安全头 v2 ADR，明确 magic、vault ID、字段编码、AAD、算法标识、KDF 参数边界和未知字段策略。
- 明确迁移前自动备份、暂存文件、同步、替换、回滚和启动时残留恢复协议。
- 更新威胁模型与安全测试用例，给迁移中断和安装包替换分配可追踪编号。
- 评审本文件的兼容矩阵，不接受“读取失败后按新保险库创建”或静默降低 KDF 参数。

完成定义：

- 文档之间没有版本号、边界或术语冲突。
- 每个失败点都有“原文件是否改变、残留文件如何处理、下次启动如何恢复”的明确答案。
- 每个兼容矩阵单元格至少对应一个自动化或人工测试。
- 评审通过前不进入 M3.2。

执行证据：

- [版本规则](../10-release-and-operations/VERSIONING.md)已冻结 `0.2.0-beta.1` 语义与日期条件。
- [ADR-012](10-ADR_VAULT_HEADER_V2.md)已冻结 v2 字段、规范 AAD、KDF 注册表和迁移提交协议。
- [威胁模型](../04-security/THREAT_MODEL.md)已增加格式降级、迁移中断、系统残留、升级卸载与发布身份威胁。
- [安全测试用例](../09-testing/SECURITY_TEST_CASES.md)已为兼容矩阵和失败点分配测试 ID。

### M3.2 安全头 v2 与最小迁移实现

目标：实现 v1 到 v2 的单向、可恢复迁移，并保持数据库 schema v2。

- 先为现有 v1 读取路径建立固定虚构夹具和回归测试。
- 实现严格的 v1/v2 解析边界、KDF 参数范围验证和规范 AAD。
- 解锁验证成功后创建迁移前备份，再重新包装同一 DEK；不轮换 DEK，不重写全部数据库。
- 对每个文件操作故障点执行注入测试，验证失败后原保险库仍可用。
- 旧版本不得把 v2 保险库识别为空保险库或覆盖它。

执行状态：已完成代码级实现与自动化回归，证据见 [M3.2 安全头 v2 与迁移验收](../09-testing/PHASE_3_M3_2_VAULT_MIGRATION.md)。真实安装包覆盖升级与降级验证保留在 M3.5。

### M3.3 KDF 基准与升级策略

目标：在最低支持 Windows 设备上用虚构保险库确定参数，而不是预先猜测新常量。

- 记录 Argon2id 延迟、峰值内存、内存分配失败和并发解锁行为。
- 冻结允许读取的参数范围、创建新保险库的当前参数和升级触发条件。
- 升级只生成新盐并重新包装同一 DEK；失败时保留旧头和迁移前备份。
- 发布说明明确当前 Windows 构建不提供 OS 页锁定/防换出保证。

执行状态：已完成可复现基准程序、参考 Windows 设备的双并发与四并发采样、受控分配失败、工作内存零化及 Windows Job Object 受限进程实测；最低支持设备延迟/并发证据与最终参数决定仍待补，详见 [M3.3 KDF 基准与升级策略验收](../09-testing/PHASE_3_M3_3_KDF_BENCHMARK.md)。

### M3.4 Windows 生命周期与敏感残留验收

目标：关闭运行时范围的 SR-010 和发布清单中的 Windows 生命周期项目。

- 验证锁屏、休眠/唤醒、切换用户、切换应用和异常退出。
- 验证剪贴板超时、用户替换内容和剪贴板历史提示。
- 检查 WebView2 缓存、临时目录和崩溃转储不包含虚构测试秘密。
- 记录 Windows 版本、WebView2 版本、步骤、结果和清理方式。

执行状态：已实现 WTS/电源广播锁定、原生消息注入测试和流式残留扫描工具；2026-08-01 在当前 Windows 以虚构保险库完成人工锁屏、睡眠/唤醒、切换用户、切换应用、异常退出、剪贴板和 295 文件残留扫描，M3.4 当前环境验收通过，详见 [M3.4 Windows 生命周期与敏感残留验收](../09-testing/PHASE_3_M3_4_WINDOWS_LIFECYCLE.md)。

### M3.5 安装、升级、卸载与恢复

## 6. M3.1 迁移失败清单

格式 ADR 和测试计划至少覆盖：

1. 迁移前备份创建、同步或摘要计算失败。
2. v1 头解析成功但主密码、AEAD 或数据库验证失败。
3. v2 暂存头写入、同步、重读或解包验证失败。
4. 正式头替换前、替换中或替换后进程终止。
5. 回滚副本创建失败、回滚失败或残留文件同时存在。
6. 头已升级但数据库 schema 迁移未开始、进行中或提交失败。
7. 磁盘空间不足、权限变化、杀毒软件占用和只读文件系统。
8. v1/v2 头与错误数据库、错误备份清单或其他保险库拼接。
9. 未知格式、未知算法、KDF 参数过低、过高、溢出或资源分配失败。
10. 用户用旧版本打开已迁移保险库，随后再返回 M3。

所有失败测试必须证明：不返回部分业务数据、不记录秘密、不静默创建新保险库、不覆盖最后一个已验证副本。

## 7. 虚构测试数据规则

- 使用保留示例域名，例如 `example.com`、`example.net` 和 `example.org`。
- 身份使用 `Avery Example`、`Morgan Test` 等明确虚构名称。
- 密码和 Token 使用测试专用值，并在名称中包含 `TEST-ONLY`；不得复用个人或组织凭据格式。
- 自动化测试在独立临时目录创建保险库，结束后清理；失败日志只能记录测试 ID、错误类别和文件状态，不记录主密码、字段值、DEK、KEK、Token 或恢复码。
- 人工验收开始前记录测试数据清单，结束后检查并清理剪贴板、历史、缓存、崩溃转储、临时文件、安装目录和测试保险库。

## 8. 当前首要风险

- v1 的 AAD 由字符串拼接生成，v2 必须冻结无歧义的规范编码。
- 当前加载路径要求 KDF 参数精确匹配常量，参数升级必须先建立有上下界的解析和资源限制。
- 安全头和数据库是双文件，格式迁移与 schema 迁移不能假设单文件原子性。
- 备份清单格式、头格式和 schema 版本不能共用一个 `formatVersion` 语义。
- `0.1.0` 不能读取未来 v2；降级行为和用户提示必须在迁移前定义。
- 公开分发前仍缺少独立安全评审、代码签名、许可证和真实 Windows 残留检查。

## 9. 证据与工作流

- 每个增量使用 `agent/<description>` 功能分支和 Pull Request。
- PR 必须引用对应的退出条件、测试 ID和虚构夹具清单。
- 自动化结果记录提交 SHA 和 GitHub Actions 运行链接；人工结果记录环境、步骤和产物哈希。
- `m2.6-internal` 只用于回归比较，不移动、不覆盖。
- 本计划通过评审后，从 M3.1 开始更新路线图和发布检查清单；未验证的项目不得提前勾选。
