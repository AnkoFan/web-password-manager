# 项目愿景

> 用途说明：说明项目为什么存在、为谁服务、提供什么核心价值，以及长期希望发展成什么。
>
> 状态：现行愿景 / 已按 ADR-014 与 M4 基线更新
>
> 最后更新日期：2026-07-30

## 1. 愿景陈述

打造一款完全本地、开源、安全、模块化且可持续扩展的信息管理工具，帮助用户长期、可靠地保存和查找网站账号、密码及其他重要敏感信息，不再因为遗忘登录信息而失去对账号的掌控。

软件服务于用户，数据属于用户。

## 2. 要解决的核心问题

用户拥有的网站和在线服务越来越多，同一个网站还可能存在私人、工作、测试等多个账号。依靠记忆、便签、聊天记录或散落的文本文件管理这些信息，容易出现以下问题：

- 忘记某个网站使用了哪个账号或密码。
- 同一网站的多个账号混在一起，难以区分用途。
- API Key、令牌、邮箱、恢复码等附加信息没有统一保存位置。
- 敏感数据散落在多个地方，难以备份、迁移和保护。
- 现有工具可能过于复杂、依赖云端，或不符合用户自己的组织习惯。

本项目首先解决一个明确问题：让用户能够快速找到并安全使用自己保存的网站账号信息。

## 3. 产品定位

第一阶段，本项目是一款以网站账号和密码管理为核心的本地桌面工具。

长期来看，它可以在稳定数据模型和模块化架构之上，逐步支持 API Key、访问令牌、SSH Key、软件许可证、服务器信息和其他敏感资料，但不会为了追求功能数量而牺牲安全性、清晰度和可维护性。

本项目不以“功能最多”为目标，而以以下体验为目标：

- 数据清楚：一个网站可以管理多个账号。
- 信息灵活：每个账号可以拥有多个自定义字段。
- 查找迅速：通过分类、标签和搜索快速定位信息。
- 使用直接：能够复制所需字段并打开对应网址。
- 控制明确：数据默认仅保存在用户本地，并可由用户备份和迁移。
- 结构稳定：新能力以清晰模块接入，不把所有功能堆积在同一界面或同一代码区域。

## 4. 目标用户

### 4.1 第一目标用户

- 希望在自己的 Windows 设备上管理网站账号的个人用户。
- 不希望依赖云端服务，希望自己掌控数据的用户。
- 同一个网站拥有多个账号，或需要保存额外字段的用户。
- 不具备专业技术背景，但希望软件清晰、易用的用户。

### 4.2 长期潜在用户

- 需要管理 API Key、令牌、服务器或许可证信息的开发者。
- 希望审查源码、参与改进或自行构建软件的开源社区用户。
- 需要多个独立保险库或工作区的高级个人用户。

团队共享、企业管理和跨设备同步不属于当前主要目标。

## 5. 核心价值观

### 5.1 Local First

核心功能必须可以离线使用。用户数据默认保存在本地，不因使用核心功能而被上传到远程服务。

### 5.2 Security First

敏感数据的保密性和完整性优先于便利性。安全设计必须基于明确威胁模型和成熟的加密组件，不自行发明加密算法。

### 5.3 Open Source

项目源码、设计思路和关键安全方案应当可以被公开审查。项目采用 MIT License，允许在保留版权与许可声明的前提下使用、修改和再分发。

### 5.4 Modular First

新增能力先定义边界、接口、依赖和测试，再接入主程序。模块化既用于代码组织，也用于界面和文档组织。

### 5.5 User Control

用户应能够访问、备份、导出和迁移自己的数据。项目不通过私有格式或远程账号强制绑定用户。

### 5.6 Simplicity

日常操作应当直接、易理解。模块化不等于增加操作层级，也不应迫使用户在多个页面间反复跳转。

## 6. 阶段性目标

### 6.1 第一阶段：可验证的本地 MVP

- 启动后自动打开由 Windows DPAPI 和 SQLCipher 保护的本地保险库。
- 按分类管理网站。
- 一个网站下保存多个账号。
- 为账号添加基础字段和自定义字段。
- 搜索账号信息。
- 复制账号、密码或其他字段。
- 使用系统默认浏览器打开网址。
- 关闭并重新打开软件后，数据仍能被安全读取。

### 6.2 第二阶段：达到可公开试用的质量

- 完善剪贴板保护、加密备份恢复和数据库迁移。
- 完成功能测试、安全测试和恢复场景验证。
- 提供可理解的安装、使用和安全说明。
- 明确开源许可证、安全披露和贡献流程。

### 6.3 长期方向

- 在不破坏核心体验的前提下扩展更多敏感信息类型。
- 根据真实需求评估多保险库、模板、附件和跨平台支持。
- 建立稳定、透明、可持续维护的开源项目。

长期方向不是当前版本承诺，具体能力必须经过需求、安全和架构评审。

## 7. 成功标准

项目成功不以文档数量或功能数量衡量，而以用户能否完成核心任务衡量：

- 用户能够在合理时间内找到目标网站及账号。
- 用户能够清楚地区分同一网站下的多个账号。
- 用户能够保存不固定类型的附加敏感信息。
- 核心操作无需联网。
- 静态保险库和数据库密钥不会以明文文件落盘，损坏或不完整的文件组合会安全停止。
- 用户可以理解数据保存在哪里，以及如何备份和恢复。
- 新模块的加入不要求大面积修改无关模块。

具体性能和安全指标将在非功能需求、安全模型及测试文档中定义。

## 8. 明确不作出的承诺

- 不承诺任何软件能够抵御所有攻击。
- 不承诺 DPAPI 保护的备份能够跨 Windows 用户或跨设备恢复。
- 不承诺第一版即支持所有桌面或移动平台。
- 不承诺第一版提供浏览器自动填充、云同步或团队协作。
- 不在许可证正式选择前宣称项目采用某一种开源许可证。
