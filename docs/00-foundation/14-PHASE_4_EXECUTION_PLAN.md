# 第四阶段 M4 执行计划

> 目标：在不改变 DPAPI/SQLCipher 存储边界的前提下提高单机日常使用效率
>
> 状态：M4.0 现行规范统一完成 / M4.1 待开始 / 仅虚构测试数据

## M4.0 现行规范统一

- 以 ADR-014 和 M3 冻结实现为准，清理产品愿景、功能清单、模块说明和验收文档中的旧主密码、KDF、锁定与解锁要求。
- 将 M3 已实现功能更新为“已完成”，不继续保留“所有功能均待开发”的旧状态说明。
- 保留历史阶段记录，但为历史文档增加明确的非现行提示，不改写当时的审计事实。
- 冻结 M4 范围、编号和不进入项后再修改业务代码。

退出条件：当前有效文档之间不存在会引导重新实现锁定功能的冲突要求。

## M4.1 本地排序与筛选

- 分类和网站默认采用稳定、可预测的名称排序；同名比较必须有稳定标识兜底。
- 网站列表提供最小筛选入口，复用现有安全搜索字段，不包含密码或敏感自定义字段。
- 多账号行保持现有折叠规则，排序不能丢失草稿输入或错误状态。
- 900×640 最低窗口和键盘操作继续可用。

退出条件：排序结果重启一致，筛选不会泄露敏感值，折叠与草稿状态回归通过。

## M4.2 离线密码生成器

- 由 Rust 使用操作系统安全随机源生成，不在前端使用 `Math.random()`。
- 首版参数只包含长度及大写、小写、数字、符号类别；设置合理上下限并保证至少选择一类。
- 生成结果默认隐藏，只能由用户明确显示、复制或填入当前密码输入框。
- 不写入日志、通知正文、搜索索引、Web Storage 或测试快照。
- 填入现有账号后仍需用户点击保存，不自动持久化。

退出条件：字符类别、长度边界、随机源调用、敏感面扫描和键盘流程均有测试证据。

## M4.3 回收站批量管理

- 支持选择多个已删除对象并批量恢复。
- 支持选择后永久删除，并明确显示对象数量、不可恢复后果和备份建议。
- 永久删除采用数据库逻辑删除/物理行删除语义，不宣称能够可靠擦除 SSD、文件系统快照或备份中的历史数据。
- 批量操作必须原子提交；失败时不得只处理部分选择。

退出条件：混合对象、空选择、失败回滚、焦点顺序和确认数量回归通过。

## M4.4 Windows 回归与候选冻结

- 运行前端、Rust/SQLCipher/DPAPI、npm audit、RustSec、生产构建和敏感面门禁。
- 仅用虚构数据复测新增、编辑、排序、筛选、生成密码、批量恢复和永久删除。
- 覆盖安装时继续使用可见的旧进程关闭提示，并保持应用数据目录不被安装器覆盖。
- 功能与门禁稳定后再把前端、Rust 和 Tauri 版本统一提升到 `0.3.0-beta.1`。
- 生成 Windows NSIS 候选安装包并记录文件大小和 SHA-256。

退出条件：本地与单次远程 CI 通过，候选证据写入发布清单；是否公开发布仍由项目所有者确认。

## 停止条件

- 测试或验收需要真实账号、真实密码或来源不明数据。
- 实现要求重新加入锁定、解锁或主密码流程。
- 新功能要求修改加密文件格式、扩大 Tauri 权限或增加联网能力，但尚无单独评审。
- 旧测试保险库可能被迁移、覆盖或删除。
