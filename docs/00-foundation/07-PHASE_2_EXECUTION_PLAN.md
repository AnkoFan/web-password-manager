# 第二阶段执行计划

> 用途说明：把“最小可用账号管理”拆成可开发、可测试、可验收的增量。
>
> 状态：M2.1–M2.5 已完成
>
> 最后更新日期：2026-07-30

## 1. 阶段目标

第二阶段交付一个仅限内部测试的账号管理闭环：

```text
解锁保险库
→ 创建分类
→ 创建网站和两个账号
→ 保存基础字段与自定义字段
→ 关闭并重新打开
→ 搜索、复制和打开网址
→ 软删除并恢复
```

本阶段继续只使用虚构测试数据。第一阶段安全评审、自动锁定、剪贴板定时清理和备份恢复未完成前，不宣称能够安全保存真实秘密。

## 2. 范围基线

### 必须进入内部 MVP

- 分类、网站、多账号和统一账号字段模型。
- 新增、查看、编辑和软删除。
- 删除批次及底层恢复能力。
- 网站名称、账号名称、用户名和邮箱的本地搜索。
- `http` / `https` 网址校验、复制和默认浏览器打开。
- 重启后的数据、对象关系、字段顺序和敏感属性一致性。
- P0 领域、存储、命令边界和关键界面测试。

### 第二阶段后半程

- 简化回收站界面。
- 剪贴板定时且有条件清理。
- 自动锁定、休眠锁定和基础设置。
- 加密备份与一次恢复演练。

### 暂不进入内部 MVP

- 收藏和标签。
- 密码生成器、导入导出和多保险库。
- 动态插件、云同步、浏览器扩展和团队共享。

## 4. 开发顺序

每个业务增量按以下顺序完成：

1. 领域输入、约束和错误。
2. SQLCipher 仓储与事务测试。
3. Tauri 命令及锁定边界测试。
4. 前端类型化客户端。
5. React 界面与交互测试。
6. 重启持久化或端到端验收。

不得先在界面中模拟“保存成功”，再补持久化。

## 6. 已知阻断和风险

- 当前目录没有 Git 元数据，无法用提交记录审计变更或安全回溯；进入多人或长期开发前应初始化或恢复仓库历史。
- Rust 后端已完成分类、网站、账号、字段、搜索、删除与恢复的领域、仓储和命令边界；M2.1–M2.4 已进入验收状态。
- 旧版 Phase 1 原型保险库会在解锁时事务迁移到 schema v2；当前迁移仅面向不含真实数据的内部原型，正式数据迁移仍需实现迁移前备份与恢复演练。
- `demo_fields`、固定演示秘密和演示命令已由迁移 002 与真实业务界面移除。
- SQLCipher、AEAD 和保险库格式尚未完成独立安全评审。
- SQLCipher `cipher_memory_security` 在当前 Windows 环境因 `VirtualLock` 配额错误导致结构迁移栈溢出，现阶段保持关闭并列为安全评审阻断项。
- 收藏和标签在产品文档中属于候选，不作为 M2.1 至 M2.4 的前置条件。

## 7. 阶段完成定义

- 核心闭环可在 Windows 桌面构建中运行。
- 所有 P0 验收标准有对应自动化或记录式验收证据。
- 不存在已知的无提示数据丢失或跨对象误修改。
- 重启后数据及关系保持一致。
- 锁定状态不能读取、搜索、显示或复制保险库内容。
- 测试数据、日志和错误消息不包含真实秘密。
- 已知安全限制在 README、路线图和变更记录中一致。
