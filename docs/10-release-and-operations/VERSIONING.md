# 版本规则

> 状态：M3 版本策略已冻结
>
> 最后更新日期：2026-07-31

## 1. 目标

项目使用可追踪、可比较且不会把内部构建误认为公开发布的版本规则。应用版本与安全头、数据库 schema、备份清单格式分别演进。

## 2. 应用版本

应用遵循 SemVer `MAJOR.MINOR.PATCH[-PRERELEASE]`：

- `MAJOR`：发生公开 API、数据可移植性承诺或用户工作流的重大不兼容变化。
- `MINOR`：增加向后兼容功能，或进入新的公开测试阶段。
- `PATCH`：不改变数据格式语义的兼容修复。
- `beta.N`：功能范围已冻结，但安全、兼容性和人工发布门禁仍在验证。
- `rc.N`：所有计划功能和安全修复已完成，只允许发布阻断修复。

M2 内部基线为 `0.1.0`。M3 首个公开测试候选为 `0.2.0-beta.1`。

## 3. 版本推进

| 阶段 | 版本 | 进入条件 |
| --- | --- | --- |
| M3.1–M3.5 开发 | `0.1.0` + Git 提交 SHA | 不生成被误认为公开版本的安装包 |
| M3.6 beta 候选 | `0.2.0-beta.1` | 格式、KDF、Windows 与安装升级门禁通过 |
| 后续 beta | `0.2.0-beta.N` | 修复 beta 发现的问题并重跑受影响门禁 |
| 发布候选 | `0.2.0-rc.1` | 独立安全评审阻断项关闭，许可证与签名决定完成 |
| 稳定版 | `0.2.0` | 另行批准；M3 本身不自动授权稳定发布或真实秘密使用 |

版本必须同时更新：

- 根 `package.json`。
- `src-tauri/Cargo.toml`。
- `src-tauri/tauri.conf.json`。
- `CHANGELOG.md` 与发布说明。

锁文件中的本地包版本由受支持的包管理命令更新，不手工散改。

## 4. 日期条件

不预先承诺发布日期。版本号只表示兼容和成熟度，不表示某个日历日期。创建 Git 标签或 GitHub Release 前必须：

1. 通过 M3 执行计划的全部适用退出条件。
2. 记录提交 SHA、安装包名称、字节长度和 SHA-256。
3. 记录 CI 运行、Windows 人工验收环境和独立安全评审结论。
4. 确认发布说明仍明确“仅虚构测试数据”或由独立批准移除该限制。

## 5. 数据格式版本

- 安全头 `formatVersion` 只描述安全头语义。
- SQLite `user_version` 与 `schema_migrations` 只描述数据库结构。
- 备份/迁移清单 `formatVersion` 只描述清单结构。
- 应用版本不能替代以上任何格式字段。

未知的更高格式或 schema 默认拒绝写入，不猜测、不降级、不创建新保险库。

## 6. Git 引用

- `m2.6-internal` 保持指向 `b594757`，不得移动。
- M3 使用 `agent/<description>` 分支和 Pull Request。
- 公开预发布标签使用带签名或经发布身份批准的 `v0.2.0-beta.N`。
- 标签只指向通过相应门禁的提交；不得把失败构建重新上传到同一标签。

## 7. 验收

- [x] 版本推进和发布日期条件已定义。
- [x] 应用版本与三类数据格式版本明确分离。
- [x] 未知未来版本采用安全拒绝。
- [ ] `0.2.0-beta.1` 的三个应用清单在 M3.6 同步更新。
- [ ] 预发布标签、产物哈希和发布说明在 M3.6 生成。
