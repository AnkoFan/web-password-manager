# 发布流程

> 状态：M3 流程已定义 / 尚无获准公开发布
>
> 最后更新日期：2026-07-31

## 1. 发布角色

- 维护者：冻结提交、运行门禁、准备候选和回应评审。
- 独立评审者：审查密码学边界、迁移恢复、Windows 残留和安装供应链，不参与被审代码的最终自我批准。
- 发布批准者：确认许可证、签名身份、仓库可见性和风险接受。

同一人可以准备候选，但不能把自测描述为独立安全评审。

## 2. 候选准备

1. 从受保护的 `main` 创建版本分支，不移动内部基线标签。
2. 确认工作树只包含候选范围，记录完整提交 SHA。
3. 同步 `package.json`、`Cargo.toml`、`tauri.conf.json`、锁文件和 `CHANGELOG.md` 的版本。
4. 运行前端、Rust/SQLCipher、RustSec、npm audit、敏感面和文档链接门禁。
5. 在最低支持设备与 Windows 人工验收设备上执行对应清单。
6. 从干净环境构建单一 NSIS x64 安装包。
7. 使用正式代码签名证书和可信时间戳服务签名。
8. 在签名后计算字节长度和 SHA-256；任何重签名都必须重新计算哈希。

## 3. 发布物

- 版本化 NSIS 安装包。
- SHA-256 清单。
- 发布说明和已知限制。
- 对应源提交/标签。
- 第三方许可证清单。
- 独立安全评审结论与已关闭阻断项列表。

不得发布测试 identifier 包、未签名技术验收包、迁移夹具或包含用户数据的缓存/转储。

## 4. 签名要求

- 证书主题必须与最终发布身份一致并含私钥。
- 签名算法使用 SHA-256。
- 必须使用可信时间戳，验证证书链、签名状态和时间戳。
- 证书私钥不得进入仓库、日志、构建产物或普通环境文件。
- CI 签名需使用受保护的密钥服务或硬件支持方案，并限制到受批准的发布环境。
- 没有证书时只能生成明确标记的内部测试包；SHA-256 不能替代发布者身份验证。

2026-07-31 检查当前用户和本机证书库，均没有可用代码签名证书。

## 5. GitHub 治理

- 仓库公开化是单独批准动作，不能由构建成功隐式授权。
- 公开前确认历史、Issue、Actions 日志和制品中不存在秘密或个人数据。
- `main` 启用禁止直接推送、必需 PR、必需前端/Rust/RustSec 检查和分支最新要求。
- 发布标签应签名或由经批准的发布身份创建，且只指向通过门禁的提交。
- GitHub Release 上传后重新下载并核对哈希与签名。

## 6. 停止条件

任一项成立即停止发布：

- 自动或人工安全门禁失败；
- 迁移/恢复不能证明保留最后一个有效副本；
- 最低设备、安装、缓存/转储或生命周期证据缺失；
- 许可证、代码签名或独立安全评审未完成；
- 候选提交、标签、安装包和哈希不能建立一一对应；
- 发现真实秘密、个人数据或未说明的审计忽略项。

## 7. 回滚与通告

- 撤回受影响安装包和哈希，不重用原标签或文件名。
- 保留问题制品的受限取证副本，不公开用户数据。
- 发布修订版并说明受影响范围、数据格式兼容性和恢复步骤。
- 已迁移为 v2 的保险库不得建议用 0.1.0 写入。
