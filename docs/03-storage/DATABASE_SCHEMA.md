# 数据库结构

> 用途说明：记录 SQLCipher 业务结构的可执行来源、版本边界和结构验收要求。
>
> 状态：迁移 001/002 与 M2.4 业务仓储已接入
>
> 最后更新日期：2026-07-30

## 1. 权威来源

第二阶段首版结构的可执行权威来源：

- `src-tauri/migrations/001_phase2_core.sql`
- `src-tauri/migrations/002_remove_prototype_data.sql`

本文解释迁移边界，不复制整份 SQL。结构修改必须新增迁移并同步本文，不能只修改文档中的示例。

当前 `PRAGMA user_version = 2`，`schema_migrations` 同时记录迁移编号。保险库安全头格式版本与数据库结构版本相互独立。

新建保险库会初始化唯一的 `vault_meta` 记录。旧版 Phase 1 原型保险库在解锁并通过密码、SQLCipher 和标记完整性验证后，以单一事务执行迁移 001、迁移 002 并初始化 `vault_meta`；迁移失败不会提交部分结构。

## 2. 迁移 001

迁移建立：

| 表 | 职责 |
| --- | --- |
| `schema_migrations` | 记录业务结构迁移 |
| `vault_meta` | 单保险库逻辑元数据 |
| `categories` | 分类、排序和软删除状态 |
| `websites` | 网站、所属分类、网址和软删除状态 |
| `accounts` | 多账号、所属网站和软删除状态 |
| `account_fields` | 统一基础字段与自定义字段 |
| `deletion_groups` | 父子对象级联软删除批次 |

## 3. 迁移 002

迁移 002 删除第一阶段的 `demo_fields` 演示表，并记录 schema v2。`metadata` 继续作为保险库内部标记使用；生产命令和界面不再包含固定演示秘密或演示读取路径。

## 4. 关键约束

- 实体标识为 16 字节随机 UUID v4。
- 分类、网站和账号保留 `vault_id`。
- 网站使用 `(category_id, vault_id)` 复合外键，账号使用 `(website_id, vault_id)` 复合外键，阻止跨保险库关系。
- 分类名在活跃保险库范围唯一。
- 账号显示名在活跃网站范围唯一。
- 字段标签和非空系统角色在账号内唯一。
- `password` 角色或 `password` 类型必须标记为敏感。
- 活跃对象没有删除批次；已删除对象必须同时具有 `deleted_at` 和 `deletion_group_id`。
- 外键删除使用 `RESTRICT`，软删除和永久清理由显式事务控制。

## 5. 索引边界

迁移为导航、排序、名称搜索、字段角色和回收站时间建立索引。

不为以下内容建立持久化明文索引：

- 密码。
- Token、恢复码和其他敏感自定义字段。
- 任意标记为敏感的字段值。

## 6. 事务边界

以下操作必须在单一事务中完成：

- 创建账号及初始字段。
- 编辑账号及完整字段集合。
- 同级重排。
- 父对象及后代软删除。
- 按删除批次恢复。
- 永久清理删除批次。
- 后续结构迁移。

事务提交前不得向界面返回成功。

## 8. 开放问题

- 分类、网站、账号和字段标签使用 NFKC 加 Unicode 小写转换；后续导入流程需复用同一规则。
- SQLCipher 显式兼容参数仍需安全评审。
- Windows 测试中 `cipher_memory_security = ON` 在创建完整业务结构时因 `VirtualLock` 配额错误触发栈溢出，当前未启用；需要评估进程工作集配额、SQLCipher 版本行为和可接受的内存保护方案。
- 迁移记录与保险库元数据使用实际 UTC Unix 毫秒。
- 当前 0/1→2 自动迁移只面向不含真实数据的内部原型；公开使用前必须增加迁移前加密备份与失败恢复演练。
- 未知字段类型的只读保留需要在领域/仓储层设计后决定物理表示。
