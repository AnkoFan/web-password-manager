# 备份与恢复

> 状态：普通 SQLite 本机备份
>
> 最后更新：2026-08-01

## 格式

```text
plaintext-backups/<backup-id>/
├─ manifest.json
└─ password-manager.db
```

数据库和备份均未加密。清单记录格式版本、备份 ID、创建时间、schema 版本、文件长度和 SHA-256。摘要用于发现意外损坏，不是密码学认证。

## 创建

应用通过 SQLite `VACUUM INTO` 从活动连接创建一致副本，检查副本完整性与应用标记后写入清单，再把临时目录重命名为最终备份目录。创建过程中无需锁定应用或输入密码。

## 验证

恢复前检查：

- 目录名与清单备份 ID 一致；
- 清单格式和 schema 版本受支持；
- 文件长度与 SHA-256 匹配；
- `PRAGMA integrity_check` 返回 `ok`；
- 应用标记、schema 和单一元数据行有效。

## 恢复

备份先复制到暂存文件并验证。随后关闭当前连接，把活动数据库改名为回滚副本，再替换为暂存数据库。替换后重新打开验证；失败则恢复回滚副本。成功后重新加载应用。

损坏备份在替换当前数据库前被拒绝。

## 限制

- 备份可被任何具有文件读取权限的人直接打开。
- 同设备备份不能防御磁盘损坏、勒索软件或设备丢失。
- 未实现异地复制、自动轮换、用户选择目录或恢复旧 SQLCipher 备份。
- 旧 `backups` 与 `migration-backups` 目录不会出现在新备份列表中。
