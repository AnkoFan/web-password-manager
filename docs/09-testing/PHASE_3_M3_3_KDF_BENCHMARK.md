# M3.3 KDF 基准与升级策略验收

> 日期：2026-08-01
>
> 状态：参考设备顺序/并发基准与受限内存安全失败已通过 / 最低支持设备证据待补

## 固定配置

- 算法：Argon2id 1.3（版本 19）。
- 当前写入配置：`argon2id-19-m65536-t3-p1`。
- 参数：64 MiB、3 次迭代、并行度 1、32 字节输出。
- v2 允许解析的绝对资源边界：64–256 MiB、3–10 次迭代、并行度 1–4、32 字节输出。
- 只有注册表中的精确配置可以执行 KDF；位于绝对边界内但尚未注册的组合也会在派生前拒绝。
- 不允许在内存压力或配置错误时静默降低参数。

## 可复现方法

基准程序只使用固定的 `TEST-ONLY` 密码和盐，不读取或创建用户保险库：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\scripts\kdf-benchmark.ps1 `
  -Samples 10 `
  -ConcurrentWorkers 2
```

脚本使用 release 构建，预热一次后记录 10 次顺序派生、两个并发派生、进程峰值工作集，以及不包含主机名和用户名的系统规格。机器可读结果见
[M3 KDF Windows 基准证据](evidence/M3_KDF_BENCHMARK_WINDOWS.json)。

四工作线程压力采样使用相同方法，仅把 `-ConcurrentWorkers` 改为 `4`。证据同时记录实际基准可执行文件的 SHA-256，见
[M3 KDF Windows 四并发证据](evidence/M3_KDF_BENCHMARK_WINDOWS_CONCURRENT_4.json)。

## 2026-08-01 受控分配失败路径

- Argon2 工作内存改为由应用显式分配，使用 `Vec::try_reserve_exact` 在填充工作块前检查分配结果。
- 分配失败返回固定的非敏感错误：“可用内存不足，无法安全派生保险库密钥”；不降低 KDF 参数，不返回部分密钥。
- Argon2 `zeroize` 特性已启用，显式工作块在离开派生路径时清零。
- 自动测试使用不可能的工作块数量触发容量溢出/分配拒绝，验证返回受控错误而不进入 Argon2 计算。
- Windows 子进程在输出就绪标记后被加入 Job Object；测试读取其 1.52 MiB 当前私有内存，将进程内存上限设为 17.52 MiB，再触发需要 64 MiB 工作内存的 Argon2id。
- 受限子进程正常退出并返回预期的受控错误标记；未降级参数，未开始密钥包装或保险库文件操作。

这关闭了“受限 Windows 进程安全失败”路径，但不替代在 8 GiB / 4 逻辑处理器最低支持设备上的实际延迟和并发验收。

## 升级策略

1. 新保险库和 v1 到 v2 迁移均写入当前注册配置。
2. 解锁 v2 时先验证数值绝对边界，再查找精确配置；未知配置在 Argon2id 执行前拒绝。
3. 将来新增配置必须分配新的稳定配置 ID、在最低支持设备上完成同一套基准，并增加迁移中断回归。
4. 只有在旧配置成功解锁且迁移快照验证完成后，才允许用新盐和新 nonce 重新包装同一 DEK。
5. 内存分配失败、进程资源限制或并发压力均返回失败；不得改用更低参数重试。

## 尚未关闭

- 在项目声明的最低支持 Windows 硬件上重复采样。
- 根据最低设备结果决定保留当前配置或登记新的当前写入配置。

在以上两项完成前，M3.3 不标记完成，也不勾选“目标设备 KDF 基准”安全评审项。
