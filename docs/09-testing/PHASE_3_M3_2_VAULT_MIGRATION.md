# M3.2 安全头 v2 与迁移验收

> 日期：2026-07-31
>
> 状态：自动化实现与回归通过 / Windows 安装升级路径待 M3.5

## 范围

- 新保险库使用安全头 v2。
- 安全头 v1 在完整验证后迁移到 v2。
- schema v0/v1/v2 与 v1 头组合在修改前创建持久迁移快照。
- v2 头使用规范 AAD、严格字段解析、已知 KDF 配置和数据库 vault ID 绑定。
- 迁移中断后恢复唯一回滚头，不把残留状态识别为空保险库。

## 实现

- v2 头包含 `WPMVAULT` magic、规范 UUID、嵌套 KDF 与 XChaCha20-Poly1305 包装信息。
- AAD 使用 ADR-012 的 102 字节固定编码，不依赖 JSON 键顺序和空白。
- 新建保险库时先生成一个 vault ID，并同时写入头和数据库 `vault_meta.id`。
- v1 继续只接受 M2.6 的精确 KDF 与包装算法；v2 先执行绝对边界，再匹配已知 KDF 配置。
- 迁移快照包含原头、SQLCipher 数据库、长度、schema、SHA-256 和清单；提交后立即重新验证。
- schema 事务完成后才写 v2 暂存头；暂存头必须重读、解包同一 DEK 并匹配数据库 ID。
- 头替换使用回滚头；启动时正式头缺失且只有一个回滚头时自动恢复。
- 正式头、数据库或迁移残留任一存在时，创建命令均拒绝覆盖。

## 未在本增量关闭

- 最低支持 Windows 设备的 KDF 基准属于 M3.3。
- 真实 `0.1.0` 安装包覆盖升级、降级和卸载属于 M3.5。
- 系统级锁屏、休眠、缓存和崩溃转储属于 M3.4。
- 独立安全评审仍是公开发布阻断项。
