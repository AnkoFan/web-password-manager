# 安全测试用例

> 状态：M2.6 基线完成 / M3 用例已冻结
>
> 最后更新日期：2026-07-31

所有自动化夹具和人工验收只使用明确标记的虚构数据。日志、截图、缓存和测试报告不得包含主密码、DEK、KEK、字段秘密、Token 或恢复码。

## 密码学与存储

| ID | 用例 | 预期 | 类型 |
| --- | --- | --- | --- |
| SEC-001 | RFC 9106 Argon2id 已知答案 | 输出完全匹配 | 自动 |
| SEC-002 | IETF XChaCha20-Poly1305 草案已知答案 | 密文与标签完全匹配 | 自动 |
| SEC-003 | 错误主密码 | 解包失败，不返回内部错误 | 自动 |
| SEC-004 | v1 盐、nonce、AEAD 标签或 AAD 被修改 | 安全拒绝 | 自动 |
| SEC-005 | SQLCipher 页面单字节被修改 | 完整性检查拒绝 | 自动 |
| SEC-006 | 数据库被截断 | 解锁拒绝 | 自动 |
| SEC-007 | 安全头与数据库来自不同保险库 | 解锁拒绝 | 自动 |
| SEC-008 | KDF 参数超出支持值 | 派生前拒绝 | 自动 |
| SEC-009 | 备份摘要或密文损坏 | 不覆盖当前保险库 | 自动 |
| SEC-010 | v2 AAD 固定向量 | 与 JSON 键顺序和空白无关，输出完全匹配 | 自动 |
| SEC-011 | v2 magic、vault ID、KDF、nonce 或包装值被修改 | 安全拒绝，不返回部分数据 | 自动 |
| SEC-012 | v2 未知字段、算法、格式或 KDF 配置 | 派生和写入前拒绝 | 自动 |
| SEC-013 | v2 vault ID 与数据库 `vault_meta.id` 不同 | 解锁拒绝 | 自动 |

## 迁移与恢复

| ID | 用例 | 预期 | 类型 |
| --- | --- | --- | --- |
| MIG-001 | v1 + schema v2 固定虚构夹具 | 创建迁移快照并升级为 v2，业务数据不变 | 自动 |
| MIG-002 | v1 + schema v0/v1 | 快照先于 schema 与头迁移，最终为 v2/schema v2 | 自动 |

| MIG-007 | 多个操作 ID 或多个有效候选同时存在 | 不自动猜测，要求人工恢复 | 自动 |
| MIG-008 | 磁盘满、只读目录或文件被占用 | 保留最后一个已验证组合 | 故障注入/Windows |
| MIG-009 | 旧版打开 v2 后返回 M3 | 旧版不覆盖，M3 仍可解锁 | Windows |
| MIG-010 | 高于当前的 schema | 保持文件不变并提示升级应用 | 自动 |
| MIG-011 | 未知备份/迁移清单版本 | 替换前拒绝 | 自动 |
| MIG-012 | 迁移错误与日志扫描 | 不包含虚构测试秘密或密钥材料 | 自动 |

## 运行命令

```powershell
npm.cmd run check:frontend
npm.cmd audit --audit-level=moderate
scripts\cargo-test.cmd
```

GitHub Actions 已运行并通过 M2.6 的 RustSec `audit-check`；M3 的每个 Pull Request 继续执行本文件列出的自动化门禁。Windows 与故障注入用例必须在对应增量的验收记录中提供环境、步骤和结果证据。
